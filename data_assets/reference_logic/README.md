# 参考逻辑目录

本目录用于保存可复用的业务逻辑参考文件，服务于后续 SQL、ETL 和存储过程开发。

## 已登记文件

| 文件               | 用途                                                 | 使用限制                                                                                                     |
| ---------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `MTS_OBJECT.sql` | MTS 参考口径、对象结构与字段能力依据                               | 可作为逻辑口径和筛选条件的参考来源；每次复用必须记录对象、字段、条件和出处行号或检索关键字。                                                           |
| `ALL_PRC.sql`    | 数据库全量存储过程导出（crmdm schema，约 145 个过程定义，含头注释、来源表、目标表） | 开发前检索相似业务逻辑（JOIN、WHERE、日期、去重、聚合口径）的参考来源；只读参考，不得直接整段复制为新过程，复用逻辑必须记录过程名、段落号或检索关键字，并与当前需求、Mapping、DDL 逐项核对。 |
| `ALL_TB.sql`     | 数据库全量表结构 DDL 导出（crmdm schema，约 527 张表，含表/字段注释）     | 开发前核对存量表结构、字段类型与字段口径的参考来源；表结构以仓库 `data_assets/ddl/` 为准，两者冲突时以仓库 DDL 为准并将差异标记【待确认】。                       |

## 开发前强制检索顺序

1. 根据当前需求的指标、源表、目标表、统计维度和业务动作，在本目录检索相似逻辑。
2. 检查 `data_assets/stored_procedure/` 中已经开发的存储过程，核对相同或相近的 `JOIN`、`WHERE`、日期、去重、聚合和异常处理条件。
3. 优先复用已验证的逻辑；若不能复用，必须在需求或变更说明中记录差异原因。
4. 参考逻辑只能作为依据，最终实现仍需与当前需求、Mapping、DDL 和记忆卡片逐项核对。

## MTS 参考口径追溯

当逻辑口径或筛选条件依据 `MTS_OBJECT.sql` 时，必须在代码注释或需求/变更文档中使用以下格式之一：

```sql
-- 参考口径来源: data_assets/reference_logic/MTS_OBJECT.sql
-- 参考对象: MTS.<TABLE_NAME>；字段: <COLUMN_NAME>
-- 参考条件: <具体WHERE/JOIN/状态条件>；依据定位: <行号或检索关键字>
```

```text
参考口径来源：data_assets/reference_logic/MTS_OBJECT.sql
参考对象/字段：MTS.<TABLE_NAME>.<COLUMN_NAME>
参考条件：<具体条件>
依据定位：<行号或检索关键字>
```

## 文件命名建议

* 存储过程逻辑：`<主题>_<逻辑名称>.md` 或 `<主题>_<逻辑名称>.sql`

* 指标口径逻辑：`<指标编码>_<指标名称>.md`

* 通用条件逻辑：`<来源表或主题>_<条件名称>.md`

文件应包含：适用场景、输入表及字段、关联条件、过滤条件、日期口径、去重规则、聚合粒度、输出字段、已知限制和来源过程。

## 维护规则

* 只保存已经确认或已经在项目中验证过的逻辑，不保存未经确认的猜测方案。

* 参考文件发生变化时，记录变更日期、变更原因和影响的存储过程。

* 新开发过程使用参考逻辑后，应在过程注释、需求记忆卡片或变更说明中保留可追溯引用。

* 新增文件必须在“已登记文件”中补充用途和使用限制。

* 使用 `MTS_OBJECT.sql` 的每一个逻辑口径或筛选条件必须单独标记具体出处；不得只写笼统的“MTS参考”。
