# 存储过程日期参数规则

适用范围：所有新增或修改的 CRM 业务存储过程。存量过程仅在后续进入需求开发流程时按本规则改造。

## 基准日期

- `V_SYSDAT` 是当前跑批快照日期，格式必须为 `YYYYMMDD`。
- `V_SYSDAT` 仅可用于输入校验、运行日志和源表快照等值关联，例如 `t.data_date = V_SYSDAT`。
- 不得直接基于 `V_SYSDAT` 使用 `TO_DATE`、`TRUNC`、`ADD_MONTHS`、`LAST_DAY` 或日期加减推导月、季、年等业务边界。

## 日期参数映射

每个相对业务日期必须声明语义明确的具名变量，并由 `sys_fun_deal_date(V_SYSDAT, n)` 初始化。不得在业务 SQL 中直接调用该函数，也不得复用语义不一致的日期参数。

| 编号 | 日期语义 |
|---|---|
| 1 | 上一日（跑批日期的上一日） |
| 2 | 上月末 |
| 3 | 上季末 |
| 4 | 上年末 |
| 5 | 上上日 |
| 6 | 上上月末 |
| 7 | 上上季末 |
| 8 | 上上年末 |
| 9 | 当月初 |
| 10 | 当月末 |
| 11 | 当季初 |
| 12 | 当季末 |
| 13 | 当年初 |
| 14 | 当年末 |
| 15 | 上月初 |
| 16 | 上季初 |
| 17 | 上年初 |
| 18 | 30 天承接窗口开始日 |
| 19 | 三年历史清理边界 |
| 20 | 1月前 |
| 21 | 6月前 |

如需新的相对业务日期，从 `22` 起顺序编号，并在使用前更新本规则、需求记忆卡片及审核证据。

## 实现与审核

- 在 `DECLARE` 区声明参数，并在初始化区由函数赋值；变量名必须表达日期业务语义，并在行尾注释标注编号和日期含义。
- 源字段日期解析、按记录自身日期的计算可以使用 `TO_DATE` 或 DATE 运算；它们不能替代跑批基准日期的业务边界参数。
- 目标表中的日期字段必须输出 8 位 `YYYYMMDD`。DATE/TIMESTAMP 值使用 `TO_CHAR(value, 'YYYYMMDD')`；已校验的 `V_SYSDAT` 可以直接输出。
- 需求记忆卡片必须列出本过程实际使用的参数编号、变量名和业务含义。
- 过程审核必须逐项确认：具名参数、禁止的直接推导、目标日期格式和记忆卡片一致性。
