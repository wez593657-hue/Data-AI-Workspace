# Oracle 本地测试隔离与缺陷处理规范（强制性）

版本：v1.0
生效日期：2026-08-01
适用范围：本仓库（Kingbase-CRM-AI-Development-Guide）内所有针对本地 Oracle 环境的测试活动，
包括连接测试、数据插入、存储过程编译与运行、样例回放等。

## 1. 目的

确保本地测试活动与已确认的数据资产文件（`data_assets/` 下已确认的 DDL、存储过程、
函数、映射、字典等）在物理路径与逻辑访问上双重隔离，防止测试对数据资产产生任何
直接或间接影响，并规范测试中发现缺陷的登记、审核与修复流程。

## 2. 存放位置规范（物理路径隔离）

### 2.1 测试产物唯一存放目录

所有测试脚本、测试 DDL、转换后的过程副本、测试数据脚本、运行验证脚本，
**必须**存放于：

```text
scripts/oracle_validation/<场景名>/
```

示例：`scripts/oracle_validation/deadline_rmnd/`

### 2.2 测试报告与缺陷台账

- 测试分析报告：`docs/analysis/YYYY-MM-DD-<场景>-oracle-validation.md`
- 缺陷登记台账：`scripts/oracle_validation/<场景名>/DEFECTS.md`

### 2.3 禁止事项

以下位置 **严禁** 创建、修改、覆盖任何测试产物：

- `data_assets/`（含 DDL、存储过程、函数、映射、字典等全部子目录）
- `docs/changes/`（该目录仅用于已确认的正式变更记录）
- `requirements/`、`governance/` 中已确认的文件

测试过程对上述目录中的文件只允许 **只读引用**（如 `Get-Content` 读取源过程用于转换），
任何写入必须走第 4 节缺陷处理流程并经用户确认。

## 3. 逻辑访问隔离（数据库对象）

### 3.1 测试对象 schema 唯一指定

本地 Oracle 测试环境中新建的数据表、中间表、目标表、函数、存储过程，
**必须** 创建于测试专用 schema：`SCOTT`。

### 3.2 禁止事项

- 禁止以 `crmdm.` 或其他正式 schema 前缀创建或调用测试对象。
- 测试转换脚本必须剥离源过程文件中的 `crmdm.` 前缀（如
  `scripts/oracle_validation/<场景名>/03_convert_procs.ps1` 的强制替换规则）。
- 禁止在测试过程中 DROP / TRUNCATE / ALTER 任何正式 schema（如 `crmdm`）下的对象；
  测试仅允许操作 SCOTT 下的对象。
- 测试数据只允许插入 SCOTT 模式下的源表副本，禁止写入正式库表。

### 3.3 对象命名约定

测试对象使用与源文件一致的业务名称（如 `TMP_CDR_DTL_*`、`ADS_CUST_DEADLINE_RMND_*`），
但 schema 恒为 `SCOTT`。因 Oracle 11g 标识符长度限制（30 字符）产生的改名，
必须在转换脚本中集中登记并记录映射关系（见 DEFECTS.md）。

## 4. 缺陷处理流程（强制性）

### 4.1 发现阶段

测试中发现数据相关问题（SQL 编译错误、运行错误、结果与预期不一致、口径偏差等），
**严禁** 直接修改已确认的数据资产文件。

### 4.2 记录与标记

缺陷必须在 `scripts/oracle_validation/<场景名>/DEFECTS.md` 中登记，每条缺陷必须包含：

| 字段 | 要求 |
|---|---|
| 缺陷编号 | 格式 `DEFECT-YYYY-MM-DD-序号` |
| 状态 | 待审核（初始） |
| 具体位置 | 文件绝对路径 + 行号/代码片段 |
| 影响范围 | 受影响的过程/表/映射/调用方 |
| 复现证据 | 错误码、日志、输出片段 |
| 建议解决方案 | 明确给出修复方案（含是否需同步修改源文件） |
| 处理决策 | 由用户确认后填写：Codex 执行 / 手动处理 / 不修复 |

### 4.3 提交审核

登记完成后，将缺陷摘要与建议方案提交用户审核确认。

### 4.4 执行阶段

仅在用户明确确认后，方可执行以下之一：

1. **由 Codex 执行修改**：Codex 修改数据资产文件并附带变更文档；
2. **手动处理**：用户自行处理，Codex 不触碰数据资产文件；
3. **不修复**：记录结论并关闭缺陷。

未经用户确认，禁止执行任何数据资产文件的修改。

## 5. 权限控制规则

| 对象 | 权限 |
|---|---|
| `scripts/oracle_validation/` | 测试脚本自由读写 |
| `docs/analysis/` | 测试报告自由读写 |
| `data_assets/` | 只读引用，禁止写入 |
| `docs/changes/`、`requirements/`、`governance/` | 只读引用，禁止写入（正式变更除外，且需用户确认） |
| 本地 Oracle SCOTT schema | 自由建表/插入/编译/运行（测试） |
| 本地 Oracle 正式 schema（crmdm 等） | 禁止操作 |

## 6. 测试前流程确认（每次执行前强制）

每次执行测试前，必须逐项确认以下清单，全部满足方可开始：

- [ ] 1. 测试产物目录为 `scripts/oracle_validation/<场景名>/`，与 `data_assets/` 物理隔离
- [ ] 2. 数据库测试对象 schema 为 `SCOTT`，无 `crmdm.` 前缀引用
- [ ] 3. 本次测试未对 `data_assets/` 及已确认文件执行任何写操作
- [ ] 4. 转换脚本仅输出到测试目录，读取源文件不写回
- [ ] 5. 已检查 `DEFECTS.md`：新发现缺陷已完成登记，状态为待审核
- [ ] 6. 涉及数据资产修改的请求均处于"已确认"状态，否则不执行

确认结果须记录在测试输出首部（或测试报告"流程确认"章节）。

## 7. 违规处置

违反上述任一条款（如在 `data_assets/` 写入测试文件、直接修改已确认数据资产、
未登记缺陷即修改源文件等），应立即停止测试，如实报告并回滚已产生的变更；
未经用户确认不得恢复操作。
