# PRC_DWD_ACCT_INSUR 全面静态审查报告

- 审查日期：2026-08-05
- 审查对象：`data_assets/stored_procedure/ods_to_dwd/PRC_DWD_ACCT_INSUR.sql`
- 审查方式：仓库静态代码、模板、Mapping、DDL、既有 Oracle 验证材料交叉核对；未连接 Kingbase 数据库。
- 审查边界：本报告不修改过程，也不把历史 Oracle 测试结果表述为当前 Kingbase 运行结论。

## 结论

过程主体采用 Oracle 兼容模板的过程签名、分段日志和 `WHEN OTHERS` 回滚框架，且新增、更新目标表在最后一次提交前处于同一事务中；静态日期参数和跨层结构校验均通过。

按最新确认口径，保险源表应使用 `data_assets/ddl/ods/ybt` 下的 `YBT_YBT_*` 及 `YBT_IB_LIST_PLAT` 实体。当前过程没有使用这些表名；同时，过程引用的 `YBT_POLICY_FEE_LIST.TX_DATE` 不在现行 YBT DDL 中，且把 YBT DDL 已标注为 `YYYYMMDD` 的保单日期按 `YYYY-MM-DD` 解析。再加上交易表的单列主键不能表达该过程所依赖的一保单多笔交易，过程当前不能视为可部署版本。共享物理快照表、快照提前提交、非法参数无日志、状态值透传等问题也需要在上线前处理。

## 业务逻辑复核

### 已确认正确或不应误判为问题的内容

1. 目标表主键和快照主键均为 `(CUST_ID, ACCT_ID, PRDKT_ID, INSUR_BID_FORM_NO)`，新增的 `NOT EXISTS` 与更新的 `MERGE` 使用同一键，键口径一致。
2. `TX_TYP` 统一写空值与当前 Mapping 第 233 行一致，不应按旧版本口径要求写入 `TRAN_TYPE`。
3. 快照并非冗余表：其结果被新增和更新两个步骤复用，避免同一 ODS 聚合被计算两次。
4. `V_DATA_DATE` 直接由已校验的跑批日解析，仅用于与源记录日期比较，不属于日期规则禁止的“基于跑批日推导相对周期边界”。

### 仍需业务/接口确认的边界

| 项目 | 当前行为 | 需要确认的口径 |
|---|---|---|
| 交易日期格式 | 假设 `TX_DATE` 前十位为 `YYYY-MM-DD` | YBT 交易明细表无 `TX_DATE`；需确认应采用 `YBT_IB_LIST_PLAT.PLAT_DATE`、`TRAN_DATE` 或其他字段。所有现行保单日期字段均为 `YYYYMMDD`，需统一解析口径。 |
| 终止日期 | 终止交易日期优先，状态为 `2` 时回退保险结束日 | 状态交易与 `CONT_STATUS` 的优先级，以及“终止撤销/复效”是否应恢复金额。 |
| 保费金额 | 新单最大值加续期金额汇总；若缴费满期/超宽限期/非正常状态则清零 | 退款、撤单、补缴、重复回传是否需要冲销或去重。 |
| 法人行号 | 按 `THROW_COM` 前缀映射为 `1500/1200/1800/9999` | 是否覆盖全部机构编码及未知机构的处置规则。 |

## 推荐优化方案

### 推荐方案：先修复数据契约，再进行受控过程改造

1. 以已确认的 YBT 实体名为准修正对象引用；由接口方确认交易日期字段和交易唯一键，并同步 `YYYYMMDD` 日期格式的 DDL、Mapping、过程和测试基线。这是 F-01 至 F-03 的前置条件。
2. 改造快照为会话级临时表，或为物理快照添加不可冲突的批次标识；调度层增加同过程互斥锁。
3. 将交易表一次预聚合为“每保单首/末交易日、终止交易日、新单保费、续期次数、续期保费”后连接保单主数据，消除相关子查询。
4. 在装载目标前执行关键键、状态白名单、日期格式、金额范围、源快照行数和目标增更行数对账；异常行进入隔离表或按批次失败处理。
5. 补齐参数失败日志、独立提交步骤日志和可区分的业务错误码；清理 `V_START_DT`。
6. 业务确认期间字段语义、退款/复效口径及机构编码映射后，再改动金额和字段映射逻辑。

### 备选方案：仅保障现有流程稳定

若近期无法改造实体或过程，可由 DBA 发布兼容视图/同义词、补齐交易日期字段，并在调度层强制单实例串行执行。该方案能降低部署和并发风险，但不能解决交易唯一键与真实多交易模型的根本矛盾，且仍需补充质量对账。
