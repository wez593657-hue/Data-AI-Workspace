# 睡眠户唤醒与机构粒度口径对齐设计

日期：2026-08-05  
状态：待用户复核

## 目标

以最新确认口径为唯一基线，消除需求材料、临时表 DDL 注释和审查报告之间的冲突；本次不修改五类功能的存储过程业务代码。

## 已确认口径

1. 睡眠户唤醒：当月新增持有定期、理财或保险产品即判为已唤醒。以相关账户业务日期处于当月首日至跑批日的窗口判定，不比较历史或基线产品余额。
2. 机构归属：同一 `PERSN_LEGAL_BK_CODE + CUST_ID` 只存在一个 `ORG_ID`。`ORG_ID` 保留为展示和机构汇总维度；未在客户、法人行关联中重复书写 `ORG_ID` 不构成跨机构串数缺陷。

## 非目标

- 不改变账户日期字段、当月窗口或 `WAKE_STATE` 月内不可回退的现有过程逻辑。
- 不删除 `ORG_ID` 结果列、机构汇总或机构树处理。
- 不将唯一性约束假定为数据库物理约束；新增数据质量监控建议。

## 验收

1. 所有材料不再出现“唤醒必须基线余额为 0 且当日大于 0”的现行规则描述。
2. 审查报告不再把当前睡眠户唤醒过程列为 P0 缺陷。
3. 机构关联问题只保留为“唯一性约束监控建议”，不再列为代码数据正确性缺陷。
4. 日期参数与跨层一致性校验继续通过。
