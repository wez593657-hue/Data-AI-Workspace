# 客户经营存储过程日期与机构计算单位改造设计

## 目标

将潜力提升、到期承接、流失挽回、睡眠户唤醒和新客经营的明细、统计过程统一为 T+1 跑批日期语义，并按客户号与归属机构拆分计算。

## 日期口径

- `V_SYSDAT` 为跑批日期，也是本次业务数据日期；跑批执行时点对应现实自然日的上一日。
- 跑批业务数据日期：`V_DATA_DATE := V_SYSDAT`。
- 需求语义的上一日使用 `sys_fun_deal_date(V_SYSDAT, 1)`。
- 上月末、上季末、上年末分别使用函数参数 `2`、`3`、`4`。
- 上上日、上上月末等更早相对日期使用函数规定的后续参数，例如 `5`、`6`。
- 当前月、季、年边界依据 `V_DATA_DATE` 计算；仅用于目标表统计周期结束日的字段继续按原有周期末语义生成。

## 机构计算单位

- 明细计算单位固定为 `CUST_ID + ORG_ID`。
- 资产快照关联必须同时使用 `CUST_ID` 和 `ORG_ID`；需要法人行约束时额外关联 `PERSN_LEGAL_BK_CODE`，不以法人行替代机构关联。
- 机构、法人行输出优先取参与计算的资产快照，客户基本信息表仅补充名称、客户经理和属性。
- 统计人数按明细行的机构拆分口径汇总；已有 `CUST_ID + ORG_ID` 去重规则的过程保持该规则。

## 修改范围

- 10 个存储过程：五类经营主题的明细、统计过程。
- 5 份规则记忆卡片：新增本次版本与日期、机构口径说明。
- 不变更目标表或临时表字段定义，除非核对过程发现现有字段无法承载 `ORG_ID`。

## 校验

- 静态检查：不保留业务相对日期的 `V_SYSDAT - 1`、上月末、上季末、上年末旧表达式。
- 关联检查：资产表关联包含 `CUST_ID + ORG_ID`。
- SQL 结构检查：目标插入字段与 SELECT 列数保持一致，过程异常和日志框架不变。
- 数据库编译和样本结果比对需在 Kingbase 环境执行。
