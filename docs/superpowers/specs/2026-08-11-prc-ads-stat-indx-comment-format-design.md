# PRC_ADS_STAT_INDX_DATA 注释与格式化设计

## 目标

对 `data_assets/stored_procedure/dws_to_ads/PRC_ADS_STAT_INDX_DATA.sql` 进行仅注释和排版层面的规范化，提升可读性、可审查性与后续维护效率，不改变任何 SQL 业务逻辑、对象引用、事务边界、参数值或执行结果。

## 注释规范

1. 在过程头部新增“参数说明”和“内部变量说明”，说明名称、数据类型、默认值或来源、取值范围及使用限制。
2. 新增“字段使用说明”区，仅说明过程实际使用的目标表、临时表、配置表与源表关键字段。字段类型和枚举值以项目 DDL 为准；DDL 未定义的值域明确标注“以源系统字典为准”。
3. 每个步骤统一使用三级注释：步骤目标、输入与过滤规则、输出与边界约束。
4. 复杂 CTE 增加职责说明，明确范围构建、去重、聚合和结果发布的顺序。
5. 仅对业务含义不直观的表达式添加行内注释；不为常规 SQL 关键字或显而易见的别名重复添加注释。

## 格式规范

1. 统一使用四个空格缩进，不使用制表符。
2. SQL 关键字、对象名称与既有过程命名保持原样；关键字统一大写。
3. `SELECT` 字段、`INSERT` 列清单、连接条件、`CASE` 分支和长条件按逻辑分行，并对齐同级语句。
4. 块间使用单个空行，步骤间使用固定分隔线，避免无意义空行。
5. 行宽以约 120 字符为上限；无法安全拆分的日志文本或 SQL 字面量保持原样。

## 不在范围内

- 不修改指标计算公式、字段映射、过滤条件或数据范围。
- 不增加索引、DDL、动态 SQL、事务或异常处理分支。
- 不变更已有的中文日志文案语义。
- 不推测源字段枚举或业务规则。

## 验证

1. 对比格式化前后可执行语句的关键字、对象引用和参数名，确认无业务语义变更。
2. 执行 `validate_procedure_date_parameters.py` 和 `validate_cross_layer_consistency.py`。
3. 将过程转换为 Oracle 本地测试副本并执行既有 0080-0083 集成测试，确认格式化不影响编译与计算结果。
