# PRC_ADS_STAT_INDX_DATA 运行逻辑修复设计

## 目标

修复指标统计过程已确认的机构上卷、月活日期边界、字符串日期转换、事务一致性、并发执行和 A/B 聚合结果重复问题；不改变活动路径 A、目标任务路径 B 的客户范围定义，不重新引入全量客户明细临时表。

## 变更范围

1. 将 `TMP_STAT_INDX_AGGR_A`、`TMP_STAT_INDX_AGGR_B` 合并为 `TMP_STAT_INDX_AGGR`。新表保留 `PATH_CODE`，业务主键包含 `PATH_CODE`；各指标 SQL 继续按 A/B 的不同客户来源取数，但统一写入该表。
2. 步骤 7 使用 `DWD_SYS_ORG.ORG_ID` 与 `SUP_ORG_ID` 递归生成“祖先机构-后代机构”闭包关系。直接机构结果仅汇总至其真实祖先，不基于字符串包含关系判断层级；递归使用访问路径防环并限制最大 20 层。
3. `INDX_0067` 登录日期范围为当月月初至跑批业务日 `V_SYSDAT`，不再统计未来日期。`V_CURR_MTH_END` 随之删除。
4. `DWD_CUST_INDV_INFO.OPEN_DATE` 和 `DWD_ACCT_DEPO.OPEN_DATE` 仅在满足 `YYYYMMDD` 或 `YYYY-MM-DD` 格式时规范为 `YYYYMMDD` 字符串再比较；非法或空值视为不满足新增客户/新发卡日期条件，不中断整批。
5. 移除中间步骤的业务数据 `COMMIT`，只保留最终成功提交；异常时可回滚过程的全部 DML。由于 `TRUNCATE` 是隐式提交且 TMP 表为共享普通表，改用 `DELETE` 清空 TMP 表，确保清理与后续 DML 位于同一事务。
6. 过程入口使用目标数据库兼容的事务级排他锁控制同一过程的并发运行；获取失败则以明确业务错误码终止。本轮先确认 Kingbase 锁函数/语法的可编译性后写入，不以 Oracle 验证副本代替 Kingbase 锁验证。

## 数据流

```text
范围构建(A/B) -> 单一聚合临时表(PATH_CODE) -> 数据质量校验
                                           -> 祖先-后代闭包 -> ADS_STAT_INDX_DATA
```

基准表仍只在开始日前一天冻结，`NOT EXISTS` 和主键均保留。单实例锁防止两个会话同时通过防重查询后竞争写入。

## 错误处理与事务

参数校验、日期衍生、TMP 清理、范围构建、基准冻结、指标计算、结果发布属于同一业务事务。由于 `SYS_PRC_STEP_LOGS` 内部会提交事务，过程内步骤日志仅汇总在内存中；业务成功提交后再写入一条成功日志。异常日志沿用异常处理块中的独立提交。异常时业务 DML 回滚、错误日志保留。

## 验证

1. 静态扫描：不存在 `OPTION (MAXRECURSION`、`TMP_STAT_INDX_AGGR_A/B`、未防护的 `TO_DATE(REPLACE(SUBSTR(open_date` 和月末作为 0067 上限。
2. Oracle 离线副本：开始日前一天冻结、正式日统计、月中登录上限、非法开户日期不终止、四层机构上卷和重复调用。
3. Kingbase：需在目标版本执行编译、单实例锁与并发调用验证；本地 Oracle 不能作为该项结论。

## 非目标

- 不改变 `STATIS_CALIB` 当前中文值的数据契约；A/B 仅作为内部路径代码。
- 不删除基准表的 `NOT EXISTS`。
- 不建立或复用不存在的 `TMP_STAT_INDX_DTL_A/B` 客户明细表。
- 不在缺少真实数据库证据时新增或调整源表索引。
