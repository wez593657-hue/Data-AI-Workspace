# PRC_ADS_STAT_INDX_DATA 客户维度分层重构设计

## 1. 目标与边界

重构 `PRC_ADS_STAT_INDX_DATA`，将绝大多数指标的过程内临时结果收敛至非客户粒度，降低临时表数据量与重复扫描；保留活动/任务增量指标所必需的冻结客户范围和客户状态比对。

本次不变更 `ADS_STAT_INDX_DATA` 的输出结构、路径 A（营销活动）和路径 B（目标任务）业务含义、指标配置过滤、法人行号隔离以及最终机构递归上卷。

不连接数据库；验证范围为静态 SQL、DDL 和跨层一致性检查。

## 2. 指标分层

| 分类 | 指标 | 客户处理规则 |
|---|---|---|
| 客户状态增量 | `INDX_0052`、`INDX_0053`、`INDX_0054`、`INDX_0063` | 使用冻结客户范围和客户级期初/当期状态完成逐客户判断，聚合后立即丢弃客户号。 |
| 冻结范围金额增量 | `INDX_0055`、`INDX_0056`、`INDX_0058`、`INDX_0059`、`INDX_0062` | 使用冻结客户范围限定当期事实数据；金额只按最终统计粒度保存期初汇总值，不保存客户级金额。 |
| 标准期间金额指标 | `INDX_0046`、`INDX_0047`、`INDX_0048`、`INDX_0049`、`INDX_0050`、`INDX_0051` | 在源数据关联中按需要使用客户号，并在同一 SQL 内按最终统计粒度聚合；不建立客户级 TMP。 |
| 事件/去重计数/比例 | `INDX_0061`、`INDX_0067`、`INDX_0070`、`INDX_0071`、`INDX_0072` | 在单条 SQL 的源表关联中完成客户去重或比例分子分母计算，TMP 结果不保留客户号。 |
| 口径未确认 | `INDX_0066` 及当前其他被显式禁止产出的指标 | 不产出伪造零值；待业务口径和来源字段确认后另行开发。 |

## 3. 基准表设计

### 3.1 ADS_STAT_INDX_BASELINE_DTL

该表保留客户号，但只作为冻结范围与客户状态基准，不作为金额客户级计算结果表。

- 适用范围：`0052~0056`、`0058`、`0059`、`0062`、`0063`。
- 主键：`STATIS_CALIB + STATIS_DIM + INDX_CODE + DATA_BLNG + CUST_ID + PERSN_LEGAL_BK_CODE`。
- 所有适用指标均写入冻结客户成员与 `BASE_DATA_DATE`、`BASE_RUN_DATE`。
- `BASE_CUST_LVL` 仅对 `0052~0054` 有值，`BASE_MTH_AVG_AUM` 仅对 `0063` 有值；金额指标的两个客户状态字段为空。
- 已有相同主键的基准记录不覆盖。开始日前一天未成功跑批的，在活动期间补建，但仍记录原定 `BASE_DATA_DATE` 和实际 `BASE_RUN_DATE`。

### 3.2 ADS_STAT_INDX_BASELINE_SUM

该表不保存客户号，仅保存金额类期初汇总。

- 适用指标：`0055`、`0056`、`0058`、`0059`、`0062`。
- 主键：`STATIS_CALIB + STATIS_DIM + INDX_CODE + DATA_BLNG + PERSN_LEGAL_BK_CODE`。
- 写入时由同一统计键下的 `BASELINE_DTL` 冻结客户范围关联基准日事实表后一次聚合。
- 每日当前值仍须以 `BASELINE_DTL` 冻结客户范围限制事实表，再与本表期初汇总相减。

## 4. 过程数据流

1. 构建路径 A/B 的非客户指标配置范围，粒度为：路径、数据归属、活动/任务、指标、法人行号及必要日期。
2. 在活动/任务启动日前一天生成或补建 `BASELINE_DTL`，再生成 `BASELINE_SUM`。
3. 金额和事件类指标通过源数据关联后直接聚合写入非客户粒度聚合 TMP。
4. `0052~0054、0063` 使用独立客户级 CTE 或短生命周期 TMP 完成状态比较后立即汇总。
5. 聚合 TMP 的统一粒度为：`DATA_DATE + DATA_BLNG + STATIS_DIM + STATIS_CALIB + INDX_CODE + PERSN_LEGAL_BK_CODE`。
6. 最后统一进行机构递归上卷并写入 `ADS_STAT_INDX_DATA`。

## 5. 性能控制

- 删除通用客户级 `TMP_STAT_INDX_ACT_CUST`、`TMP_STAT_INDX_TSK_CUST` 和客户级金额 `TMP_STAT_INDX_BASE_VAL_A/B` 的后续传递。
- 指标配置在源头过滤，避免为未配置指标生成客户范围或扫描事实表。
- 金额指标当前值按冻结客户范围直接聚合，避免逐客户金额基准的存储和重复扣减。
- 客户状态类仅在四项指标的计算窗口保留客户粒度。
- 所有客户和业务事实关联保持 `CUST_ID + PERSN_LEGAL_BK_CODE` 联合条件。
- 机构递归仅在最终聚合完成后执行，确保底层机构完整汇总至上级。

## 6. 验证

1. 静态检查：过程不含 `SELECT *`，关联条件包含法人行号，非客户指标 TMP 不包含 `CUST_ID`。
2. DDL 一致性：两张基准表字段、主键与过程插入字段一致。
3. 指标过滤：路径 A/B 均仅产出活动/任务配置的 `INDX_CODE`。
4. 基准稳定性：相同业务主键重复运行不覆盖 `BASE_DATA_DATE`、`BASE_RUN_DATE` 和既有基准值。
5. 结果粒度：输出按 `DATA_DATE + DATA_BLNG + STATIS_DIM + STATIS_CALIB + INDX_CODE + PERSN_LEGAL_BK_CODE` 比对新旧结果。

## 7. 风险与非目标

- 本次不补齐来源字段或业务规则不足的指标；缺少口径时继续不产出。
- 数据库编译、执行计划和结果对账需要在具备 Kingbase 环境和测试数据后另行完成。
- 冻结客户范围是金额增量正确性的必要条件；不得仅保留非客户汇总基准而丢弃客户范围。
