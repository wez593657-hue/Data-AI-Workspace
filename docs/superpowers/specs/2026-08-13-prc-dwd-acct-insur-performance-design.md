# PRC_DWD_ACCT_INSUR 批处理性能优化设计

## 目标

在不改变 `PRC_DWD_ACCT_INSUR` 对 `DWD_ACCT_INSUR` 产生的字段值、行数、主键集合、参数返回码和异常传播行为的前提下，缩短全量保险账户跑批时间，减少临时表 DML 与中间提交。

## 现状与问题

当前过程依次执行以下路径：

1. 清理 `DWD_ACCT_INSUR` 和三张 `TMP_DWD_ACCT_INSUR_*` 表。
2. 将 ODS 多表关联结果写入明细临时表。
3. 扫描明细临时表，将交易日期聚合写入预聚合临时表。
4. 再次扫描明细临时表并关联预聚合临时表，写入快照临时表。
5. 将快照临时表复制到 `DWD_ACCT_INSUR`。

该路径对同一批次数据产生三次中间落盘、两次额外回读、三张临时表清理和四次提交。临时表不被下游过程使用，且最终目标结果完全由第 2 至第 4 步的集合计算决定。

## 方案比较

### 方案 A：保留临时表，仅增加索引

对明细表的保单流水号、快照表主键等字段增加索引，降低聚合与关联代价。

- 优点：改动最小。
- 缺点：仍保留中间 DML、索引维护和重复扫描；全量跑批收益有限。

### 方案 B：单条集合化写入（推荐）

使用 `WITH detail AS (...)` 表达原明细层，使用 `fee_aggr AS (...)` 表达原预聚合层，再沿用原快照层 `GROUP BY` 与 `CASE` 规则，直接 `INSERT INTO DWD_ACCT_INSUR`。

- 优点：消除全部临时表 DML、回读和中间提交；保持集合处理；不新增数据库对象。
- 缺点：单条 SQL 更长，必须通过全字段差集校验确认等价。

### 方案 C：物化视图或持久化预聚合表

将保单交易聚合长期维护为物化视图或永久中间表。

- 优点：适合多个下游过程复用相同聚合。
- 缺点：当前没有复用证据，会增加刷新、运维和一致性成本，不符合当前最小实现原则。

## 已确认设计

采用方案 B。

### 数据流

```text
ODS 源表
  -> detail CTE：保留现有连接、成功状态过滤、个人客户和保单号非空过滤
  -> fee_aggr CTE：保留最近成功交易、终止交易和续期交易日期聚合
  -> 聚合 SELECT：保留四键分组、日期推算、保费汇总和全部清零规则
  -> DWD_ACCT_INSUR
```

`detail` 和 `fee_aggr` 仅在 SQL 执行期存在，不创建或清理 `TMP_DWD_ACCT_INSUR_DETAIL`、`TMP_DWD_ACCT_INSUR_FEE_AGGR`、`TMP_DWD_ACCT_INSUR_SNAP`。

### 事务与日志

过程保留参数校验和 `DWD_ACCT_INSUR` 全量删除语义，调整为两个可观测步骤：

1. 步骤 1：参数校验并清理目标表，记录成功日志后提交。
2. 步骤 2：单条集合化 `INSERT` 写入目标表，记录影响行数后提交。

加工步骤中的错误由既有异常块回滚未提交写入、记录错误日志并继续向上抛出。临时表不再属于过程事务边界的一部分。

### 等价性约束

以下内容不得变化：

- 源表、连接关系及过滤条件。
- `DWD_ACCT_INSUR` 的 26 列值、行数和四键主键集合。
- `INSUR_AMT` 的状态、趸缴、期缴和宽限期清零优先级。
- `TX_DATE`、`LAST_TX_DATE`、`ACTL_TERM_DATE`、保险期间和缴费期间日期推算。
- 有效日期参数的成功返回码、无效参数返回码及异常传播。

## 验证设计

1. 执行既有结构与业务规则脚本，覆盖 13 个保单场景、幂等、参数校验和异常恢复。
2. 执行既有交易日期回归脚本，覆盖 `TX_DATE` 与 `LAST_TX_DATE`。
3. 增加全字段双向差集校验：先由当前基线过程生成基线结果，再由优化过程生成结果，对 26 列使用 `MINUS` 双向比对。
4. 更新性能脚本，在 10,000、30,000、50,000 保单规模下记录耗时与目标行数；仅在结果等价后比较耗时。
5. 保留并发脚本作为刷新模式风险检查。该过程全量删除目标表，当前设计不承诺两个会话同时跑同一批次的结果隔离。

## 预期收益与风险

主要收益来自消除三张临时表的 `DELETE`、三次插入、两次全表读取及其索引维护。实际提升取决于 ODS 表规模、临时表索引和数据库执行计划，应以性能脚本实测为准。

主要风险是 CTE 重写时误改聚合粒度、空值行为或日期转换行为。实现将直接复用现有聚合表达式，并使用双向全字段差集验证约束风险。
