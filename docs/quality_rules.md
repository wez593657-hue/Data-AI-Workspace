# 质检规则

> 版本：v1.0 | 2026-07-27

---

## 概述

本文档定义项目的**质检规则**（HOW —— 如何验证目标达成）。质检是手段，目标是目的。每一条质检规则明确标注它服务于哪个目标。

质检分三层，由浅入深：

| 层级 | 名称 | 说明 | 执行方式 |
|------|------|------|----------|
| QA | 单文件静态检查 | 仅靠正则/文本匹配，无须跨文件比对 | 自动化 |
| QB | 跨文件内容一致性 | 需解析代码结构并跨文件比对 | 自动化 |
| QC | 业务正确性审查 | 需领域知识和人工/AI 判断 | AI + 人工 |

---

## QA 层：单文件静态检查

| 编号 | 检查项 | 服务目标 | 通过标准 |
|------|--------|---------|----------|
| QA-01 | 存储过程文件存在且非空 | G1.1 | 按需求对应的 SP 文件逐个检查，文件大小 > 0 |
| QA-02 | 存储过程头部含版本号 `vX.Y.Z` 和日期 `YYYY-MM-DD` | G2.3 | 匹配到至少一对 |
| QA-03 | 代码中不出现 `SELECT *` | G4.1 | 0 命中 |
| QA-04 | 代码中用 `TO_DATE` / `TRUNC` / `ADD_MONTHS` 直接推导业务日期边界 | G4.3 | 0 命中（内部日期数学运算除外） |
| QA-05 | 代码中使用了 `sys_fun_deal_date` 函数 | G4.3 | 至少 1 次引用 |
| QA-06 | 目标表 DDL 文件存在且非空 | G1.2 | 按需求对应的 DDL 逐个检查，文件大小 > 0 |
| QA-07 | 每个存储过程对应临时表 DDL 存在 | G1.3 | 存在 `tmp_pro_*` 对应文件 |
| QA-08 | DDL 每个列有 `--` 行内注释 | G4.4 | 所有字段均有注释 |
| QA-09 | DDL 含表注释 `COMMENT ON TABLE` | G4.4 | 存在 |
| QA-10 | DDL 含列注释 `COMMENT ON COLUMN` | G4.4 | 每列均有 |
| QA-11 | 表名前缀与文件路径层级一致 | G3.1, G3.2 | 前缀匹配目录 |
| QA-12 | 规则记忆卡片含版本历史表 | G2.1 | 匹配到 `vX.Y.Z` 格式版本号行 |
| QA-13 | 规则记忆卡片含需求-代码映射表 | G2.1 | 匹配到映射表标记 |
| QA-14 | 存储过程格式统一：关键字大写、缩进 4 空格、逻辑块间空行 | G4.4 | 0 命中小写关键字；缩进/空行符合规范 |
| QA-15 | 存储过程文件头注释含五要素（名称/功能/参数/需求版本/变更记录） | G4.4 | 五要素齐全；无法确认版本时须标注 `【待确认】` |
| QA-16 | 存储过程每条 SELECT 字段、WHERE/JOIN 条件、函数、参数后均有行内注释 | G4.4 | 除结构关键字行外无未注释代码行 |
| QA-17 | 存储过程同代码块内行内注释对齐、字段别名使用大写 `AS` 并对齐 | G4.4 | 对齐校验工具通过 |

## QB 层：跨文件内容一致性检查

| 编号 | 检查项 | 服务目标 | 通过标准 |
|------|--------|---------|----------|
| QB-01 | 代码版本号与对应规则记忆卡片版本号一致 | G2.2 | 完全一致 |
| QB-02 | DDL 列名和顺序与存储过程 INSERT 列名和顺序一致 | G1.2, G1.3 | 完全一致 |
| QB-03 | 临时表字段在后续查询中被实际使用 | G1.3 | 所有字段有引用，无孤儿字段 |
| QB-04 | 存储过程引用的表/视图在 DDL 目录中有记录 | G1.1 | 所有 FROM / JOIN 表可追溯 |

## QC 层：业务正确性审查

| 编号 | 检查项 | 服务目标 | 通过标准 |
|------|--------|---------|----------|
| QC-01 | 计算口径与规则记忆卡片一致（阈值、周期规则、指标定义） | G1.1 | 所有阈值和条件逐项比对通过 |
| QC-02 | 关键关联条件完整（CUST_ID / ORG_ID / COMP_ID / BAL_TYPE / DATA_DATE） | G1.1 | 关键字段关联到位，无笛卡尔积风险 |
| QC-03 | `sys_fun_deal_date` 参数索引与业务语义匹配 | G4.3 | 参数 n 的语义与变量用途一致 |
| QC-04 | 边界条件正确（左闭右开、去重逻辑、NULL 处理） | G1.1 | 与卡片定义一致 |
| QC-05 | 统计类存储过程的汇总维度与卡片一致（GROUP BY 字段、法人行分组等） | G1.1 | 分组字段包含卡片要求的全部维度（仅当存在统计表 SP 时检查） |
| QC-06 | 修改范围不超出本次需求涉及的文件 | G1.1~G1.3 | 未修改非需求范围文件 |
| QC-07 | 大数据量查询有索引覆盖（执行计划无全表扫描） | G4.5 | 执行计划通过 |
| QC-08 | 无硬编码敏感信息（密码、密钥） | - | 0 命中 |
| QC-09 | Excel Mapping 变更点与 DDL 变更点一一对应 | G5.1, G5.2 | 无遗漏、无多余变更 |
| QC-10 | 受影响的存储过程 INSERT 列与 DDL 保持一致 | G5.3 | 列名和顺序匹配 |
| QC-11 | 修改前已输出变更范围并经用户确认 | G5.4 | 有确认记录 |

## 质检执行原则

1. **质检不能成为目标**。质检通过≠产出物完美，业务正确性需人工最终确认。
2. **QA → QB → QC 依次执行**。前一层不通过则不进入下一层。
3. **每一项失败必须修复后重新从 QA 开始**，不可跳过层级。
4. **QC 层可选择性执行**。简单修改跳过性能和安全检查，复杂需求全量执行。
