# ADS_STAT_INDX_RULE_PARAM 移除验证报告

日期：2026-08-12  
范围：`PRC_ADS_STAT_INDX_DATA` 的 `INDX_0080`、`INDX_0081`、`INDX_0083`，以及参数表 DDL、接入文档和 Oracle 离线验证环境。

## 结论

代码资产已经移除对 `ADS_STAT_INDX_RULE_PARAM` 的依赖。原六项参数已转换为两条计算路径一致的静态 SQL 条件；新客窗口统一调用 `sys_fun_deal_date(v_sysdat, 27)`。由于本次未连接 Kingbase 数据库，数据库对象删除、权限回收、存储过程编译及生产数据对账必须在目标库执行后才可确认，不能由静态检查替代。

## 固定业务口径

| 指标 | 静态条件 | 口径来源 |
| --- | --- | --- |
| `INDX_0080` | 180 天新客窗口、存款余额 `>= 100` 元、持有产品数 `>= 2` | 窗口：`sys_fun_deal_date.sql` 的 `WHEN 27`；100、2：原参数表已确认初始化值 |
| `INDX_0081` | `mct_type = 'personage'`、年度成功收款金额 `>= 500` 元 | 原参数表已确认初始化值 |
| `INDX_0083` | `TRIM(acct_typ) IN ('01', '02')`、卡号非空 | 允许集合为已确认固定口径；账户类型枚举参考 `MTS_OBJECT.sql` 的 `MTS.CDS_TB_CASH_ACCT_INFO.ACCT_TYPE`，检索关键字 `comment on column MTS.CDS_TB_CASH_ACCT_INFO.acct_type` |

`MTS_OBJECT.sql` 未提供 `UEPP_PAY_*` 和 `DWD_ACCT_DEPO` 的同名对象定义，因此 `0080` 的 100/2 以及 `0081` 的 `personage`/500 未标注为 MTS 来源，避免伪造可追溯性。

2. `0080` 的 100 元与 2 类条件、`0081` 的个人商户和 500 元条件、`0083` 的 `01/02` 条件均同时存在于 A、B 路径。
3. DDL 已删除 `ADS_STAT_INDX_RULE_PARAM`；指标准入不再依赖独立规则或参数表。
4. Oracle Harness 删除参数表及指标规则表清理、建表和种子数据，确保离线编译环境不再依赖上述对象。
