## 二、两条数据路径

### 路径A: 营销活动 (STATIS\_CALIB='08'，path\_code='08')

```
DWD_MKT_ACT_INFO (MKT_ACT_ID, ACT_BGN_DATE, STATIS_STOP_DATE)
  → DWD_MKT_ACT_ORG_REL → PRTSPT_ORG
  → DWD_MKT_TSK_INFO (MKT_ACT_ID, CUST_ID, MKT_PERSN, MKT_PERSN_ORG)

客户范围: 仅 DWD_MKT_TSK_INFO 中的客户
一个 MKT_ACT_ID → 按 DWD_MKT_ACT_TARGT 配置的 INDX_ID 产出对应指标
STATIS_DIM = MKT_ACT_ID
跑批: [ACT_BGN_DATE, STATIS_STOP_DATE] 每天
```

### 路径B: 目标任务 (STATIS\_CALIB='09'，path\_code='09')

```
DWD_MKT_INDX_TSK (TSK_ID, MKT_ACT_ID→关联Excel, RSV_OBJ, RSV_OBJ_ID, TSK_BGN_DATE)
  → 机构下理财经理 → DWD_CUST_MAN → 所有客户

客户范围: 机构下所有理财经理名下客户
一条 DWD_MKT_INDX_TSK → 产出对应的那一个指标
STATIS_DIM = TSK_ID
跑批: [TSK_BGN_DATE, STATIS_STOP_DATE] 每天
```

### 关联关系

```
MKT_PERSN = POST_ID AND MKT_PERSN_ORG = ORG_ID (DWD_SYS_POST)
理财经理→客户: DWD_CUST_MAN (MNG_TYP=1, MNGR_POST_ID=POST_ID)
机构层级: DWD_SYS_ORG (ORG_ID→SUP_ORG_ID 递归)
机构→理财经理: DWD_SYS_POST (ORG_ID, JOB_CLS='C', POST_STATE=有效)
```

## 三、机构汇总规则

```
网点→支行→分行→总行(递归SUP_ORG_ID)
每层DATA_BLNG=层级汇总值(包含所有下级+机构内客户经理)
各机构PERSN_LEGAL_BK_CODE独立
```

### DATA\_BLNG数据归属产出:

- 营销活动: PRTSPT\_ORG(汇总行) + MKT\_PERSN(理财经理行)

- 目标任务RSV\_OBJ=0: 本机构+所有下级机构+机构内客户经理，分别产出

- 目标任务RSV\_OBJ=1: 下发机构CREAT\_ORG + RSV\_OBJ\_ID(接收对象)，分别产出

## 五、持久化上期基准明细

表: `ADS_STAT_INDX_BASELINE_DTL`，用于冻结活动/任务启动前客户明细的上期值，避免活动期间源表删除、快照滚动或重跑导致上期值漂移。

### 5.1 适用指标

`INDX_0052`、`INDX_0053`、`INDX_0054`、`INDX_0055`、`INDX_0056`、`INDX_0058`、`INDX_0059`、`INDX_0062`、`INDX_0063`。

`0047` 使用独立的 `DEPO_VALUE_INIT` 基数来源，不纳入本次客户上期基准表；`0050/0051` 继续保持年初/月末比较口径；`0057/0060` 为余额净增指标（余额基准入 `BASELINE_SUM`，不进 `BASELINE_DTL`）；`0066` 需要贷款账户级风险分类基准；`0067` 取标签表当天活跃标志（不冻结基准）；`0070~0072` 为事件、卡账户或滚动窗口指标。

### 5.2 客户维度分层规则

- `ADS_STAT_INDX_BASELINE_DTL` 仅保留 `0052~0054、0063` 的客户状态基准。

- `ADS_STAT_INDX_BASELINE_MEMBER` 按活动/任务、归属和客户冻结一次全部增量指标的共同考核范围；`0055`、`0056`、`0057`、`0058`、`0059`、`0060`、`0062` 的期初值只写入无客户维度的 `ADS_STAT_INDX_BASELINE_SUM`。

- 仅 `0052~0054、0063` 在过程内进行短生命周期客户级状态比较；其余指标不得建立或传递带 `CUST_ID` 的通用 TMP 表。

- 冻结明细保留完整考核客户范围，以区分“无候选客户”与“基准漏冻结”。高频客户状态 TMP 必须前置过滤：`0052` 仅保留期初等级 `<4` 且当前等级 `>=4` 的客户，`0053` 仅保留期初 `<6` 且当前 `>=6` 的客户，`0054` 仅保留期初 `<7` 且当前 `>=7` 的客户；`0063` 仅保留期初或当前月日均 AUM 落入临界区间的客户。

- 客户号可以存在于源表关联、`COUNT(DISTINCT ...)` 和冻结范围表中，但聚合 TMP 与 ADS 最终结果均不包含客户维度。

### 5.3 主键与字段

业务主键为：

```text
STATIS_CALIB + STATIS_DIM + INDX_CODE + DATA_BLNG + CUST_ID + PERSN_LEGAL_BK_CODE
```

基准值字段包括 `BASE_CUST_LVL`、`BASE_LOAN_BAL`、`BASE_MTH_AVG_AUM`、`BASE_YR_AVG_FIN`、`BASE_MTH_AVG_FIN`、`BASE_YR_AVG_AGEN_FIN`、`BASE_MTH_AVG_AGEN_FIN`、`BASE_FIN_BAL`（0057 理财余额）、`BASE_AGEN_FIN_BAL`（0060 代销理财余额）。

### 5.4 生成与日期规则

本过程日期参数：`V_MTH_BEGIN`（参数9，当月初）、`V_CURR_MTH_END`（参数10，当月末）、`V_MTH_END`（参数2，上月末）、`V_QRT_END`（参数3，上季末）、`V_YAR_PREV_END`（参数4，上年末）、`V_YAR_BEGIN`（参数13，当年初）、`V_180_DAY_BEGIN`（参数27，180天新客窗口开始日）、`V_NEXT_DAY`（参数31，次日，v2.4 修正：此前误记为参数28）。参数 27、31 分别按 `data_assets/function/sys_fun_deal_date.sql` 的 `WHEN 27`、`WHEN 31` 实现复核。

- Scope 仅覆盖活动/任务开始日前一天至结束日：开始日前一天仅冻结基准，开始日至结束日计算指标；开始日前一天通过 `TERM_BEGIN_DATE = V_NEXT_DAY` 精确识别（v2.4 后该触发仅用于路径08冻结与路径09首日重算）。

- 活动/任务开始后不允许补建基准（路径08，仅 0050/0051 补跑例外，§3.3b）。已开始对象缺少基准时过程必须失败退出，修复开始前一天的跑批或快照异常后再重跑，禁止以活动期间当前值或零值代替基准；路径09由每日重算段自愈覆盖。

- `BASE_DATA_DATE` 是基准业务日期，路径08固定为开始日前一天（08补跑时为实际取数快照日，已知偏差，维持原口径）；路径09固定为开始日前一天（实际取数快照日）。

- `BASE_RUN_DATE` 记录基准落库跑批日期：路径08固定为开始前一天的实际冻结跑批日期（08补跑时为补跑日）；路径09为每日重算跑批日 `V_SYSDAT`。

- 已存在同一业务主键的基准不得覆盖（仅路径08，NOT EXISTS 防重），保证活动期间上期值稳定；路径09每日按任务键 DELETE+INSERT 原地重灌，同键仅保留当日最新一行，下游 join 键不含基准日期、对取数透明。

- 基准取数分流规则（v2.4，路径08冻结/路径09重算共用）：基准日（开始日前一天）= 跑批日 → 取主表当日快照（DWS\_CUST\_ASSE\_LIAB / DWS\_CUST\_LVL\_INFO）；基准日 < 跑批日 → 取 HIS 历史快照表（DWS\_CUST\_ASSE\_LIAB\_HIS / DWS\_CUST\_LVL\_INFO\_HIS）；DWS\_CUST\_CLASSFIVE 自带 data\_date 全历史，统一按 data\_date=基准日 取。

- 基准快照不完整时，不得以 `NVL(...,0)` 生成 `0063` 或金额汇总基准；`BASELINE_SUM` 保持缺失，并在对象开始后触发过程失败，不得延迟补建。

- 当日 ADS 结果仅在全部计算和校验完成后的最终步骤替换；前序步骤失败时必须保留原当日结果。

- TMP\_STAT\_INDX\_SCOPE 主键不含 TERM\_BEGIN\_DATE，plan\_001 每日 INSERT 必须幂等防重（NOT EXISTS，v2.4 修复），进行中活动/任务多日跑批不得重复插入。

### 5.5 INDX\_0081 商户 AUM 口径

- 先按个人商户、成功收款和年度累计收款金额阈值筛选活跃商户，交易来源为 `UEPP_PAY_ORDER_INFO`。

- 通过 `UEPP_PAY_ORDER_INFO.MCT_ID = UEPP_PAY_MCT_SETTLE_ACCOUNT.MCT_ID` 获取结算账户的 `CUST_NO` 核心客户号；不得使用订单付款人 `CONSUMER_ID`。

- 同一 `MCT_ID` 可能存在多个渠道记录，按 `MCT_ID + CUST_NO` 去重。已确认同一商户号不会对应不同的 `CUST_NO`，因此不会重复累计跨客户 AUM。

- 使用 `CUST_NO = DWS_CUST_ASSE_LIAB.CUST_ID`，并限定统计日期、范围行法人行号及 `BAL_TYPE='4'`，汇总年日均 AUM。

- `DWD_CUST_MAN` 关系均为有效管户，不追加有效期或最新变更筛选；机构递归不增加法人行隔离条件。

### 5.6 INDX\_0080、0081、0083 固定口径与可追溯来源

- `INDX_0080`：新客开户日期介于 `V_180_DAY_BEGIN` 与跑批日期；活期加定期存款余额不少于 100 元；手机银行、存款、理财、贷款中至少持有 2 类。180 天窗口由 `sys_fun_deal_date(v_sysdat, 27)` 生成；100 元和 2 类为原 `ADS_STAT_INDX_RULE_PARAM` 已确认初始化值固化口径，不伪称来自 MTS 对象定义。

- `INDX_0081`：仅 `UEPP_PAY_MCT_INFO.MCT_TYPE = 'personage'` 的商户；年度成功收款金额不少于 500 元。`personage` 和 500 元为原 `ADS_STAT_INDX_RULE_PARAM` 已确认初始化值固化口径，不伪称来自 MTS 对象定义。

- `INDX_0083`：仅账户类型 `01`、`02` 且卡号非空的开户账户。账户类型枚举参考 `data_assets/reference_logic/MTS_OBJECT.sql` 中 `MTS.CDS_TB_CASH_ACCT_INFO.ACCT_TYPE`，检索关键字 `comment on column MTS.CDS_TB_CASH_ACCT_INFO.acct_type`（约第 4860 行）；该对象定义可确认 `01`、`02` 为合法账户类型，允许集合为已确认固定业务口径。

- 上述静态条件须在营销活动（A，编码08）和目标任务（B，编码09）两条路径保持一致；指标准入以营销活动目标表和任务指标子表的 `INDX_ID` 为准，不建立或引用独立指标规则、参数配置表。

## 九、临时表与基数表机制决议（v2.1，2026-08-25 业务确认）

1. **0064 基数建立时点**：活动前一日跑批即建立基数；若意外未生成，以活动内首次跑批日期为基数（现 7.0 段逻辑天然兼容）。
2. **基数表生命周期**：活动/任务结束后 3 个自然月（`ADD_MONTHS(结束日,3)`）由 plan\_006 每日巡检清理。结束日来源：A 路径 `DWD_MKT_ACT_INFO.STATIS_STOP_DATE`，B 路径 `DWD_MKT_TSK_INDX_SUB.TSK_END_DATE`（任务级一致）。结束日必有值。清理后该活动历史不可重算（业务已接受）。
3. **AGGR 汇总临时表拆分**：写入方 plan\_003\~009 各自写专属表 `TMP_STAT_INDX_AGGR_003~_009` 并段首自清；读取方 plan\_010 段首自清后合并 7 表至 `TMP_STAT_INDX_AGGR_010`，统一做空值/重复强校验再落库。旧 `TMP_STAT_INDX_AGGR` 已删除不留兼容。
4. **活动/任务编号不复用**：STATIS\_DIM 唯一，基数表按活动隔离无复用风险。
5. **支付/退款区分口径**（v2.2，2026-08-25 业务确认，适用于 0069/0078/0079/0081）：

   - `UEPP_PAY_ORDER_INFO.ORDER_TYPE` 值域仅 '00'(支付)/'01'(退款)；统一过滤 `ORDER_TYPE IN ('00','01')` + `STATUS='02'`（退款单状态同为 '02'）。

   - `ORDER_AMT` 全部为正数。金额净额化：`CASE WHEN ORDER_TYPE='01' THEN -ORDER_AMT ELSE ORDER_AMT END`；净额为负直接输出负数（不截断为 0/NULL）。

   - 笔数：支付单与退款单各计 1 笔（完全退款的交易金额 0、笔数 2）。

   - 0069/0081 分母（年累计交易量）同样净额化，`>=500` 阈值按净额（毛额≥500 但净额<500 的客户剔除）；分母为负时留存率输出负值（`NULLIF` 仅挡 0）。

   - 时间归属：退款按自身 `PAY_TIME` 落入统计区间，不与原支付单配对抵消（跨期退款单独计入本期，业务已接受）。
6. **基数指标口径按路径拆分**（v2.4，2026-09-02 业务确认，适用于 0050/0051/0052/0053/0054/0055\~0060/0062/0063/0066）：

   - 路径08（营销活动）：维持原口径——活动开始日前一天一次性冻结（NOT EXISTS 防重），活动期间沿用；0050/0051 补跑例外（§3.3b，仅路径08）。

   - 路径09（目标任务）：基准日固定为任务开始日前一天，任务期内每日跑批 DELETE+INSERT 重算（按任务键整删整插，同键仅保留当日最新行），下游取数透明。

   - 取数分流：基准日=跑批日走主表（DWS\_CUST\_ASSE\_LIAB / DWS\_CUST\_LVL\_INFO），基准日<跑批日走 HIS 表（DWS\_CUST\_ASSE\_LIAB\_HIS / DWS\_CUST\_LVL\_INFO\_HIS）；主表仅存当日跑批数据，历史数据一律在 HIS 表。DWD\_CUST\_MAN 无历史表，路径09 M 型成员名单每日按当日管户重算（已知限制）；DWD\_ACCT\_LOAN 无历史快照，0066 基准账户集/余额按当日快照（已知限制）。

   - 0066 五级分类：期初分类与当前分类均改取 `DWS_CUST_CLASSFIVE`（客户级）：期初按基准日 data\_date 取 class\_five IN ('1','2')，当前按跑批日取 class\_five IN ('3','4','5')；不再使用 DWD\_ACCT\_LOAN.CATE\_5LVL。

   - plan\_001 scope 装载加 NOT EXISTS 幂等防重（修复 TMP\_STAT\_INDX\_SCOPE 主键冲突存量缺陷：主键不含 TERM\_BEGIN\_DATE，进行中对象多日跑批裸 INSERT 会撞键）。

   - 上游依赖排序：DWS\_CUST\_CLASSFIVE 与 HIS 表须先于 plan\_002 跑批装载当日+基准日历史数据，否则 08 冻结/09 重算取不到数（调度侧确认）。

   - 决议确认（2026-09-02）：① DWS\_CUST\_CLASSFIVE 分类值 1/2/3/4/5 字典与 0066 分母 IN ('1','2') / 分子 IN ('3','4','5') 口径已获业务确认一致；② HIS 表（DWS\_CUST\_LVL\_INFO\_HIS / DWS\_CUST\_ASSE\_LIAB\_HIS）保证每个 data\_date 全量快照，路径09 每日重算按基准日取 HIS 不缺行。
