## 二、两条数据路径

### 路径A: 营销活动 (STATIS_CALIB='营销活动')

```
DWD_MKT_ACT_INFO (MKT_ACT_ID, ACT_BGN_DATE, STATIS_STOP_DATE)
  → DWD_MKT_ACT_ORG_REL → PRTSPT_ORG
  → DWD_MKT_TSK_INFO (MKT_ACT_ID, CUST_ID, MKT_PERSN, MKT_PERSN_ORG)

客户范围: 仅 DWD_MKT_TSK_INFO 中的客户
一个 MKT_ACT_ID → 按 DWD_MKT_ACT_TARGT 配置的 INDX_ID 产出对应指标
STATIS_DIM = MKT_ACT_ID
跑批: [ACT_BGN_DATE, STATIS_STOP_DATE] 每天
```

### 路径B: 目标任务 (STATIS_CALIB='目标任务')

```
DWD_MKT_INDX_TSK (TSK_ID, MKT_ACT_ID→关联Excel, RSV_OBJ, RSV_OBJ_ID, TSK_BGN_DATE)
  → 机构下理财经理 → DWD_CUST_MAN → 所有客户

客户范围: 机构下所有理财经理名下客户
一条 DWD_MKT_INDX_TSK → 产出对应的那一个指标
STATIS_DIM = TSK_ID
跑批: [TSK_BGN_DATE, STATIS_STOP_DATE] 每天
```

### 关联关系

```
MKT_PERSN = POST_ID AND MKT_PERSN_ORG = ORG_ID (DWD_SYS_POST)
理财经理→客户: DWD_CUST_MAN (MNG_TYP=1, MNGR_POST_ID=POST_ID)
机构层级: DWD_SYS_ORG (ORG_ID→SUP_ORG_ID 递归)
机构→理财经理: DWD_SYS_POST (ORG_ID, JOB_CLS='C', POST_STATE=有效)
```

## 三、机构汇总规则

```
网点→支行→分行→总行(递归SUP_ORG_ID)
每层DATA_BLNG=层级汇总值(包含所有下级+机构内客户经理)
各机构PERSN_LEGAL_BK_CODE独立
```

### DATA_BLNG数据归属产出:
- 营销活动: PRTSPT_ORG(汇总行) + MKT_PERSN(理财经理行)
- 目标任务RSV_OBJ=0: 本机构+所有下级机构+机构内客户经理，分别产出
- 目标任务RSV_OBJ=1: 下发机构CREAT_ORG + RSV_OBJ_ID(接收对象)，分别产出

## 五、持久化上期基准明细

表: `ADS_STAT_INDX_BASELINE_DTL`，用于冻结活动/任务启动前客户明细的上期值，避免活动期间源表删除、快照滚动或重跑导致上期值漂移。

### 5.1 适用指标

`INDX_0052`、`INDX_0053`、`INDX_0054`、`INDX_0055`、`INDX_0056`、`INDX_0058`、`INDX_0059`、`INDX_0062`、`INDX_0063`。

`0047` 使用独立的 `DEPO_VALUE_INIT` 基数来源，不纳入本次客户上期基准表；`0050/0051` 继续保持年初/月末比较口径；`0057/0060` 为余额净增指标（余额基准入 `BASELINE_SUM`，不进 `BASELINE_DTL`）；`0066` 需要贷款账户级风险分类基准；`0067` 取标签表当天活跃标志（不冻结基准）；`0070~0072` 为事件、卡账户或滚动窗口指标。

### 5.2 客户维度分层规则

- `ADS_STAT_INDX_BASELINE_DTL` 仅保留 `0052~0054、0063` 的客户状态基准。
- `ADS_STAT_INDX_BASELINE_MEMBER` 按活动/任务、归属和客户冻结一次全部增量指标的共同考核范围；`0055`、`0056`、`0057`、`0058`、`0059`、`0060`、`0062` 的期初值只写入无客户维度的 `ADS_STAT_INDX_BASELINE_SUM`。
- 仅 `0052~0054、0063` 在过程内进行短生命周期客户级状态比较；其余指标不得建立或传递带 `CUST_ID` 的通用 TMP 表。
- 冻结明细保留完整考核客户范围，以区分“无候选客户”与“基准漏冻结”。高频客户状态 TMP 必须前置过滤：`0052` 仅保留期初等级 `<4` 且当前等级 `>=4` 的客户，`0053` 仅保留期初 `<6` 且当前 `>=6` 的客户，`0054` 仅保留期初 `<7` 且当前 `>=7` 的客户；`0063` 仅保留期初或当前月日均 AUM 落入临界区间的客户。
- 客户号可以存在于源表关联、`COUNT(DISTINCT ...)` 和冻结范围表中，但聚合 TMP 与 ADS 最终结果均不包含客户维度。

### 5.3 主键与字段

业务主键为：

```text
STATIS_CALIB + STATIS_DIM + INDX_CODE + DATA_BLNG + CUST_ID + PERSN_LEGAL_BK_CODE
```

基准值字段包括 `BASE_CUST_LVL`、`BASE_LOAN_BAL`、`BASE_MTH_AVG_AUM`、`BASE_YR_AVG_FIN`、`BASE_MTH_AVG_FIN`、`BASE_YR_AVG_AGEN_FIN`、`BASE_MTH_AVG_AGEN_FIN`、`BASE_FIN_BAL`（0057 理财余额）、`BASE_AGEN_FIN_BAL`（0060 代销理财余额）。

### 5.4 生成与日期规则

本过程日期参数：`V_MTH_BEGIN`（参数9，当月初）、`V_CURR_MTH_END`（参数10，当月末）、`V_MTH_END`（参数2，上月末）、`V_QRT_END`（参数3，上季末）、`V_YAR_PREV_END`（参数4，上年末）、`V_YAR_BEGIN`（参数13，当年初）、`V_180_DAY_BEGIN`（参数27，180天新客窗口开始日）、`V_NEXT_DAY`（参数28，次日）。参数 27、28 分别按 `data_assets/function/sys_fun_deal_date.sql` 的 `WHEN 27`、`WHEN 28` 实现复核。

- Scope 仅覆盖活动/任务开始日前一天至结束日：开始日前一天仅冻结基准，开始日至结束日计算指标；开始日前一天通过 `TERM_BEGIN_DATE = V_NEXT_DAY` 精确识别。
- 活动/任务开始后不允许补建基准。已开始对象缺少基准时过程必须失败退出，修复开始前一天的跑批或快照异常后再重跑，禁止以活动期间当前值或零值代替基准。
- `BASE_DATA_DATE` 是基准业务日期，固定为开始日前一天。
- `BASE_RUN_DATE` 固定为开始前一天的实际冻结跑批日期，准确记录基准落库日期。
- 已存在同一业务主键的基准不得覆盖，保证活动期间上期值稳定。
- 基准快照不完整时，不得以 `NVL(...,0)` 生成 `0063` 或金额汇总基准；`BASELINE_SUM` 保持缺失，并在对象开始后触发过程失败，不得延迟补建。
- 当日 ADS 结果仅在全部计算和校验完成后的最终步骤替换；前序步骤失败时必须保留原当日结果。

### 5.5 INDX_0081 商户 AUM 口径

- 先按个人商户、成功收款和年度累计收款金额阈值筛选活跃商户，交易来源为 `UEPP_PAY_ORDER_INFO`。
- 通过 `UEPP_PAY_ORDER_INFO.MCT_ID = UEPP_PAY_MCT_SETTLE_ACCOUNT.MCT_ID` 获取结算账户的 `CUST_NO` 核心客户号；不得使用订单付款人 `CONSUMER_ID`。
- 同一 `MCT_ID` 可能存在多个渠道记录，按 `MCT_ID + CUST_NO` 去重。已确认同一商户号不会对应不同的 `CUST_NO`，因此不会重复累计跨客户 AUM。
- 使用 `CUST_NO = DWS_CUST_ASSE_LIAB.CUST_ID`，并限定统计日期、范围行法人行号及 `BAL_TYPE='4'`，汇总年日均 AUM。
- `DWD_CUST_MAN` 关系均为有效管户，不追加有效期或最新变更筛选；机构递归不增加法人行隔离条件。

### 5.6 INDX_0080、0081、0083 固定口径与可追溯来源

- `INDX_0080`：新客开户日期介于 `V_180_DAY_BEGIN` 与跑批日期；活期加定期存款余额不少于 100 元；手机银行、存款、理财、贷款中至少持有 2 类。180 天窗口由 `sys_fun_deal_date(v_sysdat, 27)` 生成；100 元和 2 类为原 `ADS_STAT_INDX_RULE_PARAM` 已确认初始化值固化口径，不伪称来自 MTS 对象定义。
- `INDX_0081`：仅 `UEPP_PAY_MCT_INFO.MCT_TYPE = 'personage'` 的商户；年度成功收款金额不少于 500 元。`personage` 和 500 元为原 `ADS_STAT_INDX_RULE_PARAM` 已确认初始化值固化口径，不伪称来自 MTS 对象定义。
- `INDX_0083`：仅账户类型 `01`、`02` 且卡号非空的开户账户。账户类型枚举参考 `data_assets/reference_logic/MTS_OBJECT.sql` 中 `MTS.CDS_TB_CASH_ACCT_INFO.ACCT_TYPE`，检索关键字 `comment on column MTS.CDS_TB_CASH_ACCT_INFO.acct_type`（约第 4860 行）；该对象定义可确认 `01`、`02` 为合法账户类型，允许集合为已确认固定业务口径。
- 上述静态条件须在营销活动（A）和目标任务（B）两条路径保持一致；指标准入以营销活动目标表和任务指标子表的 `INDX_ID` 为准，不建立或引用独立指标规则、参数配置表。
