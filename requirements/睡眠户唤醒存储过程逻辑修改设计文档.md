## 一、需求背景与修改目标

### 1.1 现状问题

旧版明细过程的睡眠户清单由过程自身计算：

```
睡眠户身份 = DWS_CUST_ASSE_LIAB 当日快照中 AUM < 100
          AND 近 365 天无 DWD_TX_ASET.JIOYCFFS='0' 主动动账
```

该判断分散在 [A] 月首复核与 [B] 当日候选两个步骤中，依赖资产快照与交易明细两张表实时计算，存在两个问题：

1. 与上游 DWS 层已发布的权威睡眠户清单 `DWS_CUST_DORMANT_ACCOUT` 口径可能存在偏差（口径双重定义）；
2. 每次跑批对大交易表重复扫描，性能开销大。

### 1.2 修改目标（含已确认决策）

以 `DWS_CUST_DORMANT_ACCOUT`（睡眠户客户信息表）作为**睡眠户身份的唯一事实来源**，取消过程内自行计算睡眠户身份。已确认决策：

| # | 决策项 | 结论 |
|---|--------|------|
| D-1 | 客户范围 | **不做个人过滤**：DORMANT 当日快照全量进入清单（不再 INNER JOIN DWD_CUST_INDV_INFO 取个人） |
| D-2 | 归属机构 | **不兜底**：ORG_ID 仅由资产快照解析，缺失置空并预警 |
| D-3 | 睡眠户计算 | **过程内禁止按资产/交易重算睡眠户**，所有睡眠户一律出自 DWS_CUST_DORMANT_ACCOUT |
| D-4 | 取数日期 | **直接取当日快照**：`data_date = V_DATA_DATE`，不取 MAX 回退 |
| D-5 | 属性/状态 | **全程计算式、无 UPDATE**：属性在写入目标表时 LEFT JOIN 计算；接触/唤醒按当月窗口 EXISTS 直接判定 |
| D-6 | 下线清理 | 下线步骤**不留占位**（TMP3/TMP4/TMP8 占位块全部删除），临时表 TRUNC 保留用于对账 |

| 时机 | 规则 |
|------|------|
| 每月月初 | 从 `DWS_CUST_DORMANT_ACCOUT` 当日快照取**全量**睡眠户（客户号 + 法人行号），作为当月清单基数 |
| 月内（每天） | 从 `DWS_CUST_DORMANT_ACCOUT` 当日快照取**新产生**的睡眠户（当日有、当月清单无），追加清单 |

当月清单**只增不减**；接触状态、唤醒状态按当月窗口（月初~跑批日）直接计算（窗口只扩大，天然不可逆）。

## 二、新旧规则对比

| 维度 | 旧规则（v2.15.0） | 新规则（v2.16.2 最终版） |
|------|-------------------|--------------------------|
| 睡眠户身份来源 | 过程自算：DWS_CUST_ASSE_LIAB(AUM<100) + DWD_TX_ASET(365天无主动动账) | 上游权威表 `DWS_CUST_DORMANT_ACCOUT`（禁止重算） |
| 月初清单构成 | 上月末 DTL 复核：仍睡眠 OR 当月新增产品 | 当日快照**全量身份**（客户号+法人行） |
| 月内清单构成 | 昨日 DTL 全部继承 + 当日新睡眠候选（同口径自算） | 昨日身份继承 + 当日快照**新产生**身份追加（NOT EXISTS 当月 BASE） |
| 客户过滤 | 个人（DWD_CUST_INDV_INFO 驱动） | **不过滤**：DORMANT 全量入清单（D-1） |
| 属性获取 | INSERT 时联查 + [D1] UPDATE 补齐 | **写入目标表时 LEFT JOIN 直接计算，无 UPDATE** |
| 接触状态 | [D2] UPDATE 累计 | **当月窗口直接 EXISTS 判定**（TMP_ADS_SLEEP_CNTCT） |
| 唤醒状态 | [D1] UPDATE 累计（不可逆） | **当月窗口直接 EXISTS 判定**（TMP_ADS_SLEEP_WAKE_PROD） |
| 归属机构 | DWS 资产快照 | DWS 资产快照，缺失置空预警，**不兜底** |
| 只增不减 | ✔（月内） | ✔（月内） |
| 下线步骤 | 占位 + 日志 | **占位全部删除**（仅保留变更记录追溯） |
| 临时表 | BASE 全字段 + DWS_WAKE + ACTIVE_TXN + CNTCT + PROD | **BASE 瘦身两列**；DWS_WAKE/ACTIVE_TXN 定义保留对账，过程不再读写 |
| 目标表与统计过程 | ADS_CUST_SLEEP_WAKE_DTL / STATIS | **不变** |

**行为变化说明**：月首清单信任上游快照全量，跨月已恢复的上月客户本月不再保留；取数日直接依赖当日快照，**当日快照未就绪时过程报错终止**，不做 T-1 回退。

## 三、数据源：DWS_CUST_DORMANT_ACCOUT（结构已确认）

### 3.1 真实表结构

| 列名 | 数据类型 | 说明 |
|------|----------|------|
| persn_legal_bk_code | varchar(4) | 客户所在法人行号 |
| data_date | varchar(8) | 快照日期，YYYYMMDD，每日一张快照 |
| cust_id | varchar(20) | 客户号 |

DDL 已落库纳管：`data_assets/ddl/dws/dws_cust_dormant_account.sql`

> ⚠️ 表名拼写为 **DWS_CUST_DORMANT_ACCOUT**（ACCOUNT），代码内引用必须一致。

### 3.2 设计结论

1. **增量方案（唯一可行）**：表内无"睡眠产生日期"字段，"新产生"定义为：**当日快照存在 且 不在当月 BASE 清单中**（NOT EXISTS）。
2. **归属机构实时解析**：ORG_ID 仅由当日资产快照解析；缺失置空，进入统计的 ORG 覆盖率预警（D-2）。
3. **取数日期**：直接 `data_date = V_DATA_DATE`（D-4）；当日快照就绪是跑批前置条件。
4. **不做个人过滤**：DORMANT 全量入清单（D-1）；客户名称在写入阶段以 LEFT JOIN 客户信息表补齐，缺失空串。

## 四、明细过程改造设计（PRC_ADS_CUST_SLEEP_WAKE_DTL → v2.16.2 最终版）

### 4.1 步骤总览（编号 '1'~'6'，无占位）

| 步骤 | 编号 | 内容 | 说明 |
|------|------|------|------|
| 参数校验与日期初始化 | '1' | 校验 V_SYSDAT；DORMANT 当日快照就绪校验；清理目标表与 TMP 表 | 含快照前置 |
| 当月产品新增预聚合 | '2' | `TMP_ADS_SLEEP_WAKE_PROD`（唤醒源，当月窗口） | 保留 |
| 当月接触预聚合 | '3' | `TMP_ADS_SLEEP_CNTCT`（接触源，当月窗口） | 保留 |
| 身份清单基底 | '4' | 月初：DORMANT 当日快照全量；月内：昨日 DTL 身份继承；仅客户号+法人行 | 无个人过滤 |
| 当日新产生身份追加 | '5' | DORMANT 当日增量（NOT EXISTS 当月 BASE） | 无个人过滤 |
| 目标表写入 | '6' | 身份 BASE + LEFT JOIN 属性 + 接触/唤醒 EXISTS 直接判定 | 无 UPDATE |

### 4.2 步骤 '1'：前置校验与清理

```sql
-- 当日快照必须就绪（D-4），未就绪直接终止，不做回退
SELECT COUNT(*) INTO V_SNAP_CNT
  FROM DWS_CUST_DORMANT_ACCOUT
 WHERE DATA_DATE = V_DATA_DATE;
IF V_SNAP_CNT = 0 THEN
  RAISE_APPLICATION_ERROR(-20003,
    'DWS_CUST_DORMANT_ACCOUT当日快照未就绪: ' || V_DATA_DATE);
END IF;
```

清理：`DELETE` 当日/三年历史目标表数据；TRUNC 五张临时表（BASE/CNTCT/PROD/DWS_WAKE/ACTIVE_TXN，后两者仅对账用途）。

### 4.3 步骤 '4'：身份清单基底（仅身份）

```
IF V_IS_MONTH_BEGIN = 'Y' THEN
    -- 月初: DORMANT 当日快照全量（不做个人过滤，D-1）
    INSERT INTO TMP_ADS_SLEEP_WAKE_BASE (PERSN_LEGAL_BK_CODE, CUST_ID)
    SELECT d.PERSN_LEGAL_BK_CODE, d.CUST_ID
      FROM DWS_CUST_DORMANT_ACCOUT d
     WHERE d.DATA_DATE = V_DATA_DATE;
ELSE
    -- 月内: 昨日 DTL 身份继承（清单只增不减）
    INSERT INTO TMP_ADS_SLEEP_WAKE_BASE (PERSN_LEGAL_BK_CODE, CUST_ID)
    SELECT y.PERSN_LEGAL_BK_CODE, y.CUST_ID
      FROM ADS_CUST_SLEEP_WAKE_DTL y
     WHERE y.DATA_DATE = V_PREV_DAY
       AND y.STATIS_CYCLE = 'M';
END IF;
```

### 4.4 步骤 '5'：当日新产生睡眠户追加（仅身份）

```
INSERT INTO TMP_ADS_SLEEP_WAKE_BASE (PERSN_LEGAL_BK_CODE, CUST_ID)
SELECT d.PERSN_LEGAL_BK_CODE, d.CUST_ID
  FROM DWS_CUST_DORMANT_ACCOUT d
 WHERE d.DATA_DATE = V_DATA_DATE
   AND NOT EXISTS (SELECT 1 FROM TMP_ADS_SLEEP_WAKE_BASE b
                    WHERE b.CUST_ID = d.CUST_ID
                      AND b.PERSN_LEGAL_BK_CODE = d.PERSN_LEGAL_BK_CODE);
```

### 4.5 步骤 '6'：目标表写入（属性计算式，无 UPDATE）

```sql
INSERT INTO ADS_CUST_SLEEP_WAKE_DTL (...)
SELECT b.PERSN_LEGAL_BK_CODE, V_DATA_DATE, b.CUST_ID,
       NVL(c.CUST_NAME, ''),        l.CUST_LVL,
       NVL(w.DEPO_CURNT_DEPO_BAL,0), NVL(w.FIXD_DEPO_BAL,0),
       NVL(w.FIN_BAL,0),            NVL(w.INSUR_BAL,0),
       CASE WHEN EXISTS (SELECT 1 FROM TMP_ADS_SLEEP_CNTCT ct
                          WHERE ct.CUST_ID = b.CUST_ID
                            AND ct.PERSN_LEGAL_BK_CODE = b.PERSN_LEGAL_BK_CODE
                            AND ct.MKT_PERSN = m.MNGR_POST_ID)
            THEN '1' ELSE '0' END,                       -- 接触: 当月窗口直接判定
       CASE WHEN EXISTS (SELECT 1 FROM TMP_ADS_SLEEP_WAKE_PROD p
                          WHERE p.CUST_ID = b.CUST_ID
                            AND p.PERSN_LEGAL_BK_CODE = b.PERSN_LEGAL_BK_CODE)
            THEN '1' ELSE '0' END,                       -- 唤醒: 当月窗口直接判定
       m.MNGR_POST_ID, w.ORG_ID, 'M'
  FROM TMP_ADS_SLEEP_WAKE_BASE b
  LEFT JOIN DWD_CUST_INDV_INFO c ON c.CUST_ID=b.CUST_ID AND c.PERSN_LEGAL_BK_CODE=b.PERSN_LEGAL_BK_CODE
  LEFT JOIN DWS_CUST_LVL_INFO l  ON l.CUST_ID=b.CUST_ID AND l.PERSN_LEGAL_BK_CODE=b.PERSN_LEGAL_BK_CODE
                                AND l.DATA_DATE=V_DATA_DATE
  LEFT JOIN DWS_CUST_ASSE_LIAB w ON w.CUST_ID=b.CUST_ID AND w.PERSN_LEGAL_BK_CODE=b.PERSN_LEGAL_BK_CODE
                                AND w.DATA_DATE=V_DATA_DATE AND w.BAL_TYPE='1'
  LEFT JOIN DWD_CUST_MAN m      ON m.CUST_ID=b.CUST_ID AND m.PERSN_LEGAL_BK_CODE=b.PERSN_LEGAL_BK_CODE
                                AND m.MNG_TYP='1'
                                AND (m.ORG_ID = w.ORG_ID OR (m.ORG_ID IS NULL AND w.ORG_ID IS NULL));
```

要点：
- 全程无 UPDATE；身份先行，属性与状态在写入时计算；
- 接触/唤醒按月窗口直接判定，窗口只扩大 → 天然"月内只增不减、状态不可逆"；
- 余额缺失按 0、ORG 缺失置空不兜底（D-2）；名称缺失空串；
- 管户经理假设 `(法人, 客户, MNG_TYP='1', ORG)` 唯一（与历史口径一致），不唯一时需加 ROWNUM 去重（评审确认）。

### 4.6 下线与保留

| 组件 | 处理 | 说明 |
|------|------|------|
| TMP_ADS_SLEEP_ACTIVE_TXN / TMP_ADS_SLEEP_DWS_WAKE / [D1]/[D2] | **占位全部删除**（D-6） | 变更历史见过程变更记录；TRUNC 保留用于对账 |
| TMP_ADS_SLEEP_WAKE_PROD（'2'） | 保留 | 唤醒判定源（当月产品新增） |
| TMP_ADS_SLEEP_CNTCT（'3'） | 保留 | 接触判定源（当月有效接触） |
| TMP_ADS_SLEEP_WAKE_BASE | 瘦身两列 | 仅存身份；存量环境需重建 |

## 五、统计过程影响（PRC_ADS_CUST_SLEEP_WAKE_STATIS）

- **逻辑不变**：仍只消费当日 `ADS_CUST_SLEEP_WAKE_DTL`，按机构层级向上汇总 + 客户经理维度统计客户数/接触率/唤醒率。
- **新增预警建议**：统计前输出 `ORG_ID IS NULL` 客户占比（机构维度将丢失该部分客户，客户经理维度不受影响）。
- **发布说明**：睡眠客户总数随明细来源切换而自然变化，需对业务披露。
