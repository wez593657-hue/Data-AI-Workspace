### Q1 — 商户(0068/0069)与个人客户如何区分？小微/个体的标识在哪个表？

**阻塞等级**: P0（不确认无法计算0068、0069）

**影响指标**: 
- 0068 支付结算年度价值商户数
- 0069 二维码收款个人活跃商户结算存款留存率

**业务背景**:
0068的价值商户判定包含两个维度的门槛：
- **小微商户**: AUM月日均≥2万 或 活期月日均≥1万
- **个体商户**: AUM月日均≥5万 或 活期月日均≥2.5万

0069同样需要区分商户类型以筛选正确的留存率计算人群。

**已知信息**:
- ODS表 `uepp_pay_mct_info` (支付商户信息) 含字段 `mct_type varchar(20)`，注释值为：
  - `company` — 企业
  - `institution` — 党政机关/事业单位
  - `otherOrganizations` — 其他组织  
  - **`personage` — 个体商户**
  - **`smallBusinesses` — 小微商户**
- `uepp_pay_mct_info` 还有 `org_id`(所属机构) / `job_id`(客户经理编号) / `sign_date`(签约日期) / `consumer_id`(客户ID)
- `uepp_pay_order_info` (支付交易流水) 有 `mct_id`(商户号) / `order_amt`(订单金额) / `pay_time`(支付时间) / `isscode`(发卡机构代码)

**需确认事项**:
1. `mct_type='personage'`(个体商户) 和 `mct_type='smallBusinesses'`(小微商户) 是否就是0068/0069所需的区分标准？
2. 商户是否有对应的CRM客户号(CUST_ID)？通过哪个字段关联（`consumer_id`? `job_id`? 还是需要联查其他表）？
3. 0068的"AUM/活期月日均"指的是商户关联的个人客户的AUM，还是商户自有的结算存款？如果关联个人客户，关联逻辑是什么？

**确认对象**: CRM业务分析师 / 支付平台技术负责人

**预期回复格式**:

```
Q1回复：
1. 商户类型使用 mct_type 字段，personage=个体商户，smallBusinesses=小微商户。
2. 商户关联CRM客户的方式: [uepp_pay_mct_info.consumer_id / job_id / 联查其他表+字段名]
3. AUM/活期口径: [关联个人客户AUM / 商户结算存款，关联逻辑: ___]
```

### Q2 — 0070绑卡"首次绑定"的判断逻辑和具体绑定记录所在表？

**阻塞等级**: P0（不确认无法计算0070、0071）

**影响指标**:
- 0070 银行卡三方支付绑卡
- 0071 银行卡三方支付绑卡率

**业务背景**:
0070定义为"我行银行卡首次绑定微信支付、支付宝、云闪付等三方支付的数量"，0071为绑定率（绑卡数/本年新增持卡客户≤70岁）。

**已知信息**:
- ODS表 `mbk_cust_acct` (手机银行账户绑定) 包含:
  - `cust_no` — 电子银行客户号 (需映射到CRM CUST_ID)
  - `acct` — 卡号
  - `acct_add_chnl` — 下挂渠道: `MB`(手机银行) / `TC`(柜面)
  - `acct_add_date` — 下挂日期 (格式YYYY-MM-DD)
  - `acct_add_time` — 下挂时间
- 该表无明确的"绑定平台类型"字段（微信/支付宝/云闪付），也无"是否首次"标志

**需确认事项**:
1. "首次绑定"的判定逻辑是什么？
   - (A) 该卡号+该三方平台在 `mbk_cust_acct` 中的首条记录？
   - (B) 该客户在该三方平台的首条绑定记录？
   - (C) 有其他绑卡记录表（不在mbk_cust_acct中）？
2. 微信/支付宝/云闪付的绑定记录是否在 `mbk_cust_acct` 中？如何区分平台（通过哪个字段）？
3. `mbk_cust_acct.cust_no`(电子银行客户号) 如何映射到CRM的 `CUST_ID`？需要联查哪个表？
4. 0071中"本年新增持卡客户且年龄≤70岁"的判定——"新增持卡"是指开户日期在当年？还是首次绑定日期在当年？

**确认对象**: 手机银行系统负责人 / CRM技术负责人

**预期回复格式**:

```
Q2回复：
1. 首次绑定判定: [方案A/B/C，或自定义逻辑]
2. 绑卡记录表: [表名+库名]，三方平台区分字段: [字段名+值域: 微信=?, 支付宝=?, 云闪付=?]
3. cust_no→CUST_ID映射: [联表名+JOIN条件]

### Q3 — 0067登录"活跃"是否有频次阈值？如何定义活跃客户？

**阻塞等级**: P1（影响统计精度，但不阻塞开发启动）

**影响指标**: 0067 手机银行活跃客户数

**业务背景**:
0067定义为"当年个人手机银行登录活跃客户数"，但未给出"活跃"的定量标准。若默认"年内登录过即算活跃"，则`mbk_cust_log_login`中有登录记录的所有客户都算——但这可能不符合业务定义（比如登录1次和登录100次视为同等活跃）。

**已知信息**:
- ODS表 `mbk_cust_log_login` (手机银行登录日志):
  - `cust_no` — 电子银行客户号
  - `lgn_date` — 登录日期 (YYYY-MM-DD)
  - `lgn_status` — 登录状态 (1=成功, 0=失败)
  - `lgn_chnl` — 登录渠道

**需确认事项**:
1. "活跃"是否有最低登录次数/天数阈值？如"当年至少登录N次"或"当年累计登录天数≥N天"？
2. 是否只统计登录成功的记录 (`lgn_status='1'`)？
3. 是否需要排除特定渠道的登录（如柜面终端）？
4. 0073(手机银行客户数新增个人客户数)和0067(活跃客户数)的"客户"口径是否一致？是否需要映射 `cust_no` → `CUST_ID`？

**确认对象**: 手机银行业务负责人

**预期回复格式**:

```
Q3回复：
1. 活跃定义: 当年登录成功次数≥[N]次 / 当年累计登录天数≥[N]天 / 无阈值(有登录即活跃)
2. 统计范围: lgn_status=[1/全部]
3. 渠道过滤: [不过滤 / 排除渠道: ___]
4. 客户映射: 与0073口径[一致/不一致，差异: ___]
```

### Q7 — 贵金属代销收入的源表和字段？

**阻塞等级**: P0（不确认无法计算0065）

**影响指标**: 0065 代销业务收入

**业务背景**:
v2.0.3需求文档明确0065代销业务收入 = 保险代销 + 贵金属代销 + 理财代销。其他两个来源已明确：
- 保险代销: `DWD_ACCT_INSUR.NEW_INSUR_AMT` (首期保费)
- 理财代销: `DWD_ACCT_FIN` (代销大类, 购买-赎回)
- 贵金属代销: **未确定**

**已知信息**:
- `DWD_CUST_INDV_KYC.BK_OUTER_GOLD` 为"行外贵金属"(客户在其他银行持有的贵金属)，**不是本行代销数据**
- 项目中已搜索全部DDL文件，未发现本行贵金属代销明细表
- 可能的源系统：综合理财销售系统(TPS)、核心系统(CBS)、贵金属交易系统

**需确认事项**:
1. 本行贵金属代销业务的交易记录存储在哪个ODS源表？表名和库名？
2. 代销收入的字段名是什么（手续费/佣金字段）？
3. 贵金属代销是否需要区分类别（如实物贵金属、积存金、账户贵金属）？
4. 若当前系统中无贵金属数据，0065是否暂时只含保险+理财（后续再补充）？

**确认对象**: 贵金属业务负责人 / CRM数据仓库负责人

**预期回复格式**:

```
