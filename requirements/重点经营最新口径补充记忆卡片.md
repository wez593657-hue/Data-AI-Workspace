# 重点经营最新口径补充记忆卡片

版本：v1.0.0  
确认日期：2026-08-05  
适用功能：到期承接、新客经营、潜力提升、流失挽回、睡眠户唤醒

## 一、睡眠户唤醒

唤醒定义为**本月新增持有**定期、理财或保险产品。判断相关账户业务日期是否落在当月首日至跑批日窗口内；不要求历史产品余额为 0，也不以当日余额大于 0 的增量比较作为必要条件。

因此，`IS_WAKE=1` 表示本月窗口内存在符合范围的新增持有账户记录，`WAKE_STATE='1'` 表示该睡眠客户在本月已唤醒。月内状态按现有规则保持为 1，不因后续日期没有新增记录而回退。

## 二、客户与机构粒度

对本卡片适用的 DWS/ADS 数据，确认以下业务数据特性：

`PERSN_LEGAL_BK_CODE + CUST_ID` 只对应一个 `ORG_ID`。

`ORG_ID` 仍须保留在明细输出、机构统计和机构层级展开中，用于展示、汇总和权限范围识别；但在已确认该唯一性约束的数据源中，客户与法人行关联未重复写 `ORG_ID` 不构成跨机构串数缺陷。

## 三、质量控制

该唯一性是已确认的业务数据特性，不等同于数据库物理唯一约束。上线前应增加数据质量监控：

```sql
SELECT PERSN_LEGAL_BK_CODE, CUST_ID
FROM DWS_CUST_ASSE_LIAB
WHERE DATA_DATE = :data_date
GROUP BY PERSN_LEGAL_BK_CODE, CUST_ID
HAVING COUNT(DISTINCT ORG_ID) > 1;
```

若监控发现同一法人行、同一客户出现多个机构，应按数据异常处理并暂停相关统计口径确认，不得自行选择机构值。

## 四、覆盖关系

本补充卡片覆盖早期材料中与本次确认冲突的两类描述：

- “唤醒基线余额=0且当日余额>0”仅作为历史版本记录，不再作为当前业务规则。
- “同法人行同客户可能存在多个归属机构”仅作为历史假设，不再作为当前已确认数据特性。

原规则记忆卡片和变更记录保留，用于追溯；开发、审查和验收以本卡片为当前口径。
