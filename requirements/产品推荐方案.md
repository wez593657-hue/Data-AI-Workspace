## 1. 方案目标

本方案用于在不引入复杂算法模型的前提下，基于明确、可解释、可审计的业务规则，对在售产品进行筛选和排序，并输出推荐结果。

本方案的目标如下：

* 满足合规要求，仅推荐风险适配且当前可售的产品

* 保持推荐逻辑可解释，便于业务、合规及审计复核

* 提升推荐落地性，避免因过滤条件过多导致无产品可推

* 支持后续参数化配置和系统化实施

## 2. 模型总体结构

本模型采用两层决策机制：

1. **硬过滤**

   仅保留两条底线规则，对不满足要求的产品直接剔除

2. **评分排序**

   对通过硬过滤的候选产品进行 100 分制评分，并按总分从高到低输出推荐结果

模型流程如下：

```text
全量在售产品池 -> 硬过滤 -> 候选产品池 -> 评分排序 -> 输出Top 3推荐结果
```

## 3. 硬过滤规则

硬过滤仅保留以下两项：

| 规则编号 | 规则名称 | 规则定义               | 处理方式     |
| ---- | ---- | ------------------ | -------- |
| F1   | 风险适配 | 产品风险等级不得高于客户风险承受等级 | 不满足则直接剔除 |
| F2   | 产品可售 | 产品必须处于当前可售状态       | 不满足则直接剔除 |

### 3.1 风险适配说明

客户风险承受等级示例：C1、C2、C3、C4、C5

产品风险等级示例：R1、R2、R3、R4、R5

适配原则：产品风险等级 <= 客户风险承受等级

示例：

* C1客户仅可推荐R1产品

* C3客户可推荐R1、R2、R3产品

### 3.2 产品可售说明

产品可售需至少满足以下条件：

* 产品状态为在售

如后续业务需要，也可扩展更多可售性标签，但本版本客户确认稿仅保留上述基本定义。

## 4. 评分模型设计

对通过硬过滤的候选产品，采用"维度百分制得分 × 权重"的方式进行排序。评分维度仅保留以下四项：

| 评分维度     | 权重  | 评分目的                     |
| -------- | --- | ------------------------ |
| 收益吸引力    | 35% | 衡量产品在同类产品中的收益竞争力         |
| 期限匹配度    | 30% | 衡量产品期限与客户历史持有产品期限偏好的匹配程度 |
| 风险舒适度    | 20% | 衡量产品风险是否处于客户更易接受的区间      |
| 历史偏好/熟悉度 | 15% | 衡量产品是否符合客户过往购买偏好与熟悉程度    |

总分计算公式如下：

```text
产品总分 = 收益吸引力得分 × 35% + 期限匹配度得分 × 30% + 风险舒适度得分 × 20% + 历史偏好/熟悉度得分 × 15%
```

其中，各评分维度内部均按百分制进行评分，单维度得分区间为 0 分至 100 分。

## 5. 评分规则明细

### 5.0 候选产品粒度（V1.0.2 新增，业务确认口径）

* 普通定期存款以"产品 × 存期档"作为独立候选参与评分与排序，每个存期档各自计算 A/B/C/D 四维得分与综合总分；

* 同一产品的不同存期档可作为多个候选并存于 Top 3 输出结果中，不合并、不去重；

* 候选数据来源：DWD\_PRDKT\_INFO\_ZB（产品信息表子表），其粒度即"产品编号 × 存期 × 币种"；

* 智能存款、理财仍以产品为单一候选（属性表一行一产品）；

* 本币人民币为默认范围，外币存期档是否参与候选见待确认事项。

### 5.1 收益吸引力

收益吸引力用于衡量产品在可比产品中的收益表现。为保证规则稳定性与可解释性，本方案采用同类产品相对收益排名，而不采用客户主观收益预期作为评分依据。

同类产品建议定义为：

```text
产品类型 + 风险等级
```

收益吸引力评分规则如下：

| 规则项 | 判断标准                     | 得分   |
| --- | ------------------------ | ---- |
| A1  | 产品预期收益率/利率位于同类产品前10%     | 100分 |
| A2  | 产品预期收益率/利率位于同类产品前10%-30% | 80分  |
| A3  | 产品预期收益率/利率位于同类产品前30%-50% | 60分  |
| A4  | 产品预期收益率/利率位于同类产品前50%-80% | 30分  |
| A5  | 产品预期收益率/利率位于同类产品后20%     | 0分   |

如暂无足够可比样本，建议给予中性分值，例如60分。

### 5.2 期限匹配度

期限匹配度用于衡量产品期限与客户近三年历史持有产品期限偏好的匹配程度。

建议基于客户历史持有产品的期限分布，识别客户偏好的主要期限区间，并据此进行匹配判断。

如客户历史持有产品期限偏好主要集中于某一期限区间，例如"3个月至6个月"，则建议按期限区间命中逻辑进行判断：

| 规则项 | 判断标准                   | 得分   |
| --- | ---------------------- | ---- |
| B1  | 产品期限落入客户历史偏好的主要期限区间    | 100分 |
| B2  | 超出主要期限区间但偏差小于等于3个月     | 80分  |
| B3  | 超出主要期限区间且偏差在3个月至6个月之间  | 60分  |
| B4  | 超出主要期限区间且偏差在6个月至12个月之间 | 30分  |
| B5  | 超出主要期限区间且偏差大于12个月      | 0分   |

当客户购买了多种期限产品，取**年日均最大**的产品期限进行匹配（落地确认 2026-09-02：期限偏好锚点由"近三年金额最大产品单点期限"调整为"近三年年日均最大产品单点期限"，年日均来源 DWS\_CUST\_ASSE\_LIAB\_CUMU\_HIS 按上年末快照，存款 PRDKT\_TYP='1'/理财 '3'，与标签表储蓄产品期限偏好口径一致；存期不做三档归并仍按单点月数参与五档评分；理财锚点取到期限为 NULL 的产品不计入）。

### 5.3 风险舒适度

风险舒适度用于衡量产品风险是否处于客户更容易接受的区间。本方案不采用"越接近客户风险上限分越高"的逻辑，而采用"风险舒适区优先"的业务规则。

同时，对风险向下兼容的产品保留及格底线分，避免对高风险承受客户可接受的低风险产品形成过度惩罚。

风险舒适度评分规则如下：

| 规则项 | 判断标准                 | 得分   |
| --- | -------------------- | ---- |
| C1  | 产品风险等级与客户可承受上限相同     | 100分 |
| C2  | 产品风险等级比客户可承受上限低1档    | 90分  |
| C3  | 产品风险等级比客户可承受上限低2档    | 80分  |
| C4  | 产品风险等级比客户可承受上限低3档    | 70分  |
| C5  | 产品风险等级比客户可承受上限低4档及以上 | 60分  |

示例：

* C3客户推荐R3产品：100分

* C3客户推荐R2产品：90分

* C3客户推荐R1产品：80分

### 5.4 历史偏好/熟悉度

历史偏好/熟悉度用于衡量产品是否符合客户过往购买习惯，提升推荐结果的接受度。

本维度建议综合以下三个参考因素进行判断：

* 产品类型是否与客户过去一年购买频次最高的大类一致

* 产品发行机构是否与客户过去一年购买最多的机构一致

* 客户过去一年是否曾购买过同类产品

历史偏好/熟悉度评分规则如下：

| 规则项 | 判断标准                  | 得分   |
| --- | --------------------- | ---- |
| D1  | 产品类型、发行机构、同类购买记录三项均命中 | 100分 |
| D2  | 命中其中两项，且包含产品类型偏好命中    | 80分  |
| D3  | 命中其中两项，但不包含产品类型偏好命中   | 60分  |
| D4  | 仅命中其中一项               | 30分  |
| D5  | 三项均未命中                | 0分   |

## 6. 推荐结果输出规则

系统对候选产品完成评分后，按综合得分从高到低排序，输出推荐结果。

推荐结果规则如下：

* 默认输出综合得分最高的前3个产品

* 若候选产品少于3个，则返回全部候选产品

* 若候选产品为空，则返回"暂无适配产品"

如发生同分情况，建议按以下优先级排序：

1. 期限匹配度高者优先
2. 收益吸引力高者优先
3. 历史偏好/熟悉度高者优先
4. 产品编号升序作为最终兜底规则

## 7. 推荐理由模板

### 7.1 理由编码

| 类别    | 推荐理由编码                                            |
| ----- | ------------------------------------------------- |
| 存款/理财 | RISK\_MATCH、TERM\_MATCH、YIELD\_TOP、HISTORY\_MATCH |

### 7.2 命中等级

各评分维度均按维度得分划分为高、中、低三个命中等级。默认分档如下，分档阈值作为推荐理由参数维护：

| 命中等级 | 维度得分   | 话术使用原则                           |
| ---- | ------ | -------------------------------- |
| 高    | 80～100 | 可作为正向推荐理由直接展示                    |
| 中    | 60～79  | 可作为一般性推荐理由；如因数据不足取得中性分，须使用数据不足话术 |
| 低    | 0～59   | 作为限制提示或弱匹配提示，不得表述为强推荐理由          |

当前风险舒适度规则的最低分为 60 分，因此风险维度通常不会出现低等级；如后续调整评分规则，应沿用上述分档并重新确认话术。

### 7.3 四类维度话术模板

#### 7.3.1 风险适配

理由编码：RISK\_MATCH。风险适配硬过滤通过后，再根据风险舒适度得分生成话术。

| 命中等级 | 标准话术模板                              | 适用说明                         |
| ---- | ----------------------------------- | ---------------------------- |
| 高    | 风险等级符合客户承受能力，风险适配度较高                | 产品风险等级与客户可承受上限相同或相差较小        |
| 中    | 产品风险等级低于客户承受上限，整体风险处于可承受范围          | 产品风险等级低于客户可承受上限，但仍通过风险适配过滤   |
| 低    | 产品风险等级与客户承受能力匹配度一般，建议结合自身风险承受能力审慎选择 | 仅用于后续规则允许低分产品时；当前规则原则上不产生该等级 |

#### 7.3.2 期限命中

理由编码：TERM\_MATCH。

| 命中等级 | 标准话术模板                      | 数据不足话术                 |
| ---- | --------------------------- | ---------------------- |
| 高    | 产品期限落入客户历史偏好的主要期限区间，期限匹配度较高 | -                      |
| 中    | 产品期限与客户历史偏好接近，期限匹配度一般       | 暂无足够历史购买记录，期限偏好按中性结果处理 |
| 低    | 产品期限与客户历史偏好偏差较大，期限匹配度较低     | 无法取得有效期限偏好，暂不判断期限匹配    |

#### 7.3.3 收益命中

理由编码：YIELD\_TOP。收益话术只描述同类产品相对表现，不承诺实际收益或未来收益。

| 命中等级 | 标准话术模板         | 数据不足话术               |
| ---- | -------------- | -------------------- |
| 高    | 同类产品收益表现靠前     | -                    |
| 中    | 同类产品收益表现处于中等水平 | 暂无足够可比样本，收益表现按中性结果处理 |
| 低    | 同类产品收益表现靠后     | 无有效收益字段，暂不判断收益表现     |

#### 7.3.4 偏好命中

理由编码：HISTORY\_MATCH。偏好话术只基于客户已记录的历史购买行为，不推断客户未表达的主观意愿。

| 命中等级 | 标准话术模板                       | 数据不足话术               |
| ---- | ---------------------------- | -------------------- |
| 高    | 产品与客户过往购买偏好一致，且客户曾购买同类产品     | -                    |
| 中    | 产品与客户部分过往购买偏好相符              | 历史购买记录有限，偏好匹配按中性结果处理 |
| 低    | 产品与客户过往购买偏好匹配度较低，或客户暂无同类购买记录 | 暂无足够历史购买记录，暂不判断偏好匹配  |

### 7.4 推荐话术组装规则

#### 7.4.1 话术组件

每个推荐结果生成一个话术组件对象，至少包含以下属性：

```text
dimension      = RISK_MATCH | TERM_MATCH | YIELD_TOP | HISTORY_MATCH
level          = HIGH | MEDIUM | LOW
score          = 0～100
message        = 对应等级的话术
data_insufficient = true | false
```

组件只允许从本章节模板中取值，禁止在代码中自由拼接未经业务确认的同义表述。

#### 7.4.2 默认组装顺序

按以下固定顺序组装，保证不同页面文案一致：

风险适配 -> 期限命中 -> 收益命中 -> 偏好命中

同一维度只输出一条话术。维度得分相同或均为中等级时，仍按上述顺序排列。

#### 7.4.3 客户概览短文案

客户概览默认采用"最多两个正向理由 + 必要限制提示"的短文案模式：

* 正向理由按"高等级优先、中等级次之"选择，最多选择 2 条；

* 若存在低等级维度，最多追加 1 条低等级限制提示；

* 若存在 data\_insufficient=true，优先使用对应的数据不足话术，不得使用"匹配""靠前"等会造成误解的表述；

* 通过"；"连接不同维度话术，末尾不重复句号；

* 四个维度均无可用话术时，使用兜底文案：该产品已通过基础准入校验，具体信息请查看产品详情。

短文案通用模板：

```text
{正向理由1}；{正向理由2}[；{限制提示}]。
```

#### 7.4.4 完整话术模板

在产品详情、推荐明细或审计记录中，可按四个维度全部展示：

```text
该产品{风险适配话术}，{期限命中话术}，{收益命中话术}，{偏好命中话术}。
```

当某维度为数据不足时，替换为该维度"数据不足话术"；当某维度没有有效数据且业务确认不展示时，删除该分句，并同步记录未展示原因。

#### 7.4.5 组装示例

示例一：风险高、期限高、收益中、偏好高：

该产品风险等级符合客户承受能力，风险适配度较高；产品期限落入客户历史偏好的主要期限区间，期限匹配度较高。

示例二：风险高、期限中、收益低、偏好低：

该产品风险等级符合客户承受能力，风险适配度较高；产品期限与客户历史偏好接近，期限匹配度一般；同类产品收益表现靠后，请结合自身需求审慎选择。

示例三：风险高、期限数据不足、收益高、偏好数据不足：

该产品风险等级符合客户承受能力，风险适配度较高；同类产品收益表现靠前；暂无足够历史购买记录，期限偏好按中性结果处理；暂无足够历史购买记录，暂不判断偏好匹配。

### 7.5 推荐理由合规约束

推荐理由只能说明规则命中情况，不得表述为收益承诺、风险承诺或购买建议。

收益话术必须使用"同类产品相对表现"，不得使用"收益最高""保证收益"等绝对化表述。

风险话术不得将"通过风险适配"表述为"没有风险"或"适合所有客户"。

期限和偏好话术只能依据已取得的结构化数据，不得根据客户年龄、家庭、收入等未参与本模型的数据补充推断。

推荐理由模板由产品推荐规则统一维护，页面展示、短信和企业微信触达使用同一套组件；触达渠道如需增加字数限制，应另行配置截断规则。

为确保后续系统开发和业务落地口径一致，建议客户对以下事项进行确认：

## 9. 结论

本方案采用"硬过滤守底线、评分排序做匹配"的业务规则模型，具有以下特点：

* 规则简单清晰，便于客户确认

* 推荐逻辑可解释，便于业务使用

* 满足基础合规要求，便于审计留痕

* 便于参数化管理，适合后续持续优化
