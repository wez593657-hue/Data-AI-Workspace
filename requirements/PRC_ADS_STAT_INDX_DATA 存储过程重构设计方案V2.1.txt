建议采用“保留现有数据契约、分层收敛计算”的 V2.1 重构方案：不改变 PRC_ADS_STAT_INDX_DATA(v_sysdat, outcde)、ADS_STAT_INDX_DATA 字段和已确认的 A/B 路径；将计算过程标准化为“范围、基准、聚合、校验、原子发布”五层。
设计目标
保持营销活动路径 A、目标任务路径 B 的客户范围和法人行隔离规则。
所有指标统一写入 TMP_STAT_INDX_AGGR_A/B，仅在步骤末端写入 ADS_STAT_INDX_DATA。
仅为必须逐客户比对的指标保留客户级数据，余额与事件类指标在源关联中直接聚合。
保留已有调用参数，不引入当前 DDL 未定义的批次号、强制标志、客群表或目标表字段。
总体流程
阶段	处理内容	输入	输出
0. 前置校验	日期格式、日期函数结果、并发运行控制	v_sysdat	可执行状态
1. 临时结果初始化	清空本过程专用 TMP 聚合结果	TMP 表	空工作区
2. 指标范围构建	按配置生成 A/B 路径、机构/经理、指标范围	营销活动/任务表	TMP_STAT_INDX_SCOPE
3. 冻结基准	仅在开始前一天冻结增量指标客户与期初值	范围、客户快照	基准成员/明细/汇总表
4. 余额预聚合	一次扫描多个日期快照，按最终粒度汇总	DWS 资产负债表	TMP_STAT_INDX_BAL_AGGR
5. 增量指标计算	使用冻结基准与当前快照计算余额、等级增量	基准表、DWS	A/B 聚合结果
6. 事件与新增指标	在源关联中完成去重和期间聚合	账户、交易、手机银行等	A/B 聚合结果
7. 结果校验	空值、重复、非法指标、范围完整性	A/B 聚合结果	校验结论
8. 原子发布	机构递归上卷后删除并重建当日 ADS 结果	A/B 聚合结果	ADS_STAT_INDX_DATA


模块设计
范围层
TMP_STAT_INDX_SCOPE 保持现有主键粒度：
PATH_CODE + STATIS_DIM + INDX_CODE + DATA_BLNG + PERSN_LEGAL_BK_CODE
A 路径仅从活动配置与营销任务客户获取范围；B 路径按机构或理财经理获取范围。所有后续 SQL 必须以该表过滤指标，禁止通过源表全量直接产出指标。
基准层
仅对等级提升、理财日均增量、贷款余额增量等需要“期初对比”的指标冻结基准。开始前一天写入，活动开始后只读，不允许补建，避免指标随历史数据回补发生漂移。

聚合层
余额指标一次读取 v_sysdat、年初、上月末、上季末、上年末等快照，汇总至机构/经理最终粒度；不得落全量客户余额临时表。事件指标通过 WITH scope_member 在单条 SQL 内关联客户范围并 COUNT(DISTINCT ...) 或 SUM(...)。

新增指标层
0080：新客窗口取 SYS_FUN_DEAL_DATE(v_sysdat, 27)；四类产品标志求和大于等于 2。
0081：按个人商户、成功收款、年累计金额不低于 500 元筛选；年日均 AUM 取 BAL_TYPE='4'。
0082：OPEN_DATE 位于考核开始日至跑批日，按 CUST_ID 去重。
0083：ACCT_TYP IN ('01','02')、CARD_NO IS NOT NULL、按 ACCT_ID 去重。
0081 的 CONSUMER_ID 与商户关联客户关系必须在投产前完成数据验收，否则只可作为待确认实现。

校验与发布
发布前增加以下校验，任一失败即抛异常并停止：
-- 不允许空业务主键或指标编码
DATA_BLNG IS NULL OR STATIS_DIM IS NULL OR INDX_CODE IS NULL

-- 不允许同一结果键重复
GROUP BY DATA_DATE, DATA_BLNG, STATIS_DIM,
         STATIS_CALIB, INDX_CODE, PERSN_LEGAL_BK_CODE
HAVING COUNT(*) > 1

-- 结果指标必须来自当前配置范围
NOT EXISTS (
  SELECT 1 FROM TMP_STAT_INDX_SCOPE s
  WHERE s.INDX_CODE = r.INDX_CODE ...
)
校验通过后才执行当日 DELETE 和最终 INSERT，随后统一 COMMIT。
事务、日志与异常
每个步骤设置独立 V_NO_ID、开始时间、行数和 LOG_STEP 日志。
过程异常统一执行 ROLLBACK，记录 SQLERRM、步骤号和耗时后重新抛出。
日志过程必须验证为独立提交或自治事务；否则失败日志会被主事务回滚，无法满足可观测性要求。
当前 TMP 表使用全局 TRUNCATE，必须建立单实例执行控制。推荐通过调度平台串行化该过程；未确认锁机制前不得并行运行同一过程。
性能策略
以 TMP_STAT_INDX_SCOPE 提前过滤业务范围。
对 DWS_CUST_ASSE_LIAB 按 DATA_DATE + BAL_TYPE + CUST_ID + PERSN_LEGAL_BK_CODE 建立或核验索引。
对事件表按时间、状态和关联键建立组合索引，例如二维码交易表的 MCT_ID + STATUS + ORDER_TYPE + PAY_TIME。
0081 先聚合活跃商户年交易额，再关联 AUM，避免对全量交易直接关联资产快照。
禁止在索引日期列外层施加函数；日期参数统一预先计算为 YYYYMMDD 字符串。
该方案以现有 DDL 和已确认业务口径为边界。确认后可据此重构正式过程、补齐校验步骤并完成 Oracle 回归测试。
