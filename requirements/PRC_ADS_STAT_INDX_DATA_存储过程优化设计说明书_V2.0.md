# PRC_ADS_STAT_INDX_DATA 存储过程优化设计说明书 V2.0

## 一、优化说明

本版本基于：

1. 原始存储过程 `PRC_ADS_STAT_INDX_DATA`
2. 当前《PRC_ADS_STAT_INDX_DATA 存储过程优化设计说明书》

进行二次细粒度优化。

优化原则：

- 不改变目标表结构。
- 不改变指标业务口径。
- 不新增业务需求。
- 保留路径A（营销活动）和路径B（目标任务）业务含义。
- 优化设计必须能够映射真实SQL实现。

当前说明书已经定义：
- 路径A：营销活动，包含机构营销活动和客户经理营销活动。
- 路径B：目标任务，包含机构目标任务和客户经理目标任务。
- 最终输出维度为机构、客户经理。

本版本进一步补充：
- 实际SQL处理层次
- 数据流转关系
- 中间结果设计
- 指标计算控制
- 法人行号隔离
- 机构递归汇总
- 事务与日志机制
- 验证方案

本版本确认：客户级仅从最终输出维度移除，不从客户范围冻结、客户状态判断和客户归属计算中移除。

# 四、路径A详细设计：营销活动

## 4.1 业务定义

路径A表示营销活动指标统计。

分类：

```
营销活动

├── 机构营销活动

└── 客户经理营销活动
```

---

## 4.2 机构营销活动

统计粒度：

```
数据日期 + 机构数据归属 + 活动/任务编号 + 统计口径 + 指标编码 + 法人行号
```

处理要求：

- 客户用于业务范围筛选。
- 最终结果不保留客户粒度。
- 机构结果进入指标聚合层。

---

## 4.3 客户经理营销活动

统计粒度：

```
数据日期 + 客户经理数据归属 + 活动/任务编号 + 统计口径 + 指标编码 + 法人行号
```

处理要求：

- 根据客户归属关系映射客户经理。
- 避免同一客户重复计入多个客户经理。

---

# 五、路径B详细设计：目标任务

## 5.1 业务定义

路径B表示目标任务完成情况。

分类：

```
目标任务

├── 机构目标任务

└── 客户经理目标任务
```

---

## 5.2 机构目标任务

统计粒度：

```
数据日期 + 机构数据归属 + 活动/任务编号 + 统计口径 + 指标编码 + 法人行号
```

输出：

- 当前完成值
- 期初基准值

> `ADS_STAT_INDX_DATA`不保存目标值；目标值仍属于任务配置数据，不在本过程输出范围内。

---

## 5.3 客户经理目标任务

统计粒度：

```
数据日期 + 客户经理数据归属 + 活动/任务编号 + 统计口径 + 指标编码 + 法人行号
```

---

# 六、客户维度处理优化

## 原则

客户不是最终统计维度。

客户仅参与：

- 活动范围判断
- 指标计算
- 客户归属映射
- 冻结客户范围与客户状态基准

最终结果：

```
机构
客户经理
指标
```

最终输出唯一粒度：

```text
DATA_DATE + DATA_BLNG + STATIS_DIM + STATIS_CALIB + INDX_CODE + PERSN_LEGAL_BK_CODE
```

其中 `DATA_BLNG` 仅为 `ORG_机构编号` 或 `MGR_经理编号` 之一，不同时保存机构和客户经理两个维度。

---

## 风险控制

必须避免：

1. 客户重复归属。
2. 多活动重复累计。
3. 多法人行号数据串联。

---

# 七、中间结果设计

## 7.1 基础预计算层

作用：

减少指标计算过程重复扫描。

保存：

- 客户编号
- 机构编号
- 客户经理编号
- 法人行号
- 指标计算基础值

## 7.2 持久化基准层

基准拆分为两张表，禁止混合不同粒度的数据行：

|表|粒度|用途|适用指标|
|-|-|-|-|
|ADS_STAT_INDX_BASELINE_DTL|统计口径 + 统计维度 + 指标 + 数据归属 + 客户 + 法人行号|冻结客户范围及客户状态基准|0052~0054、0063；同时作为金额指标的冻结客户范围|
|ADS_STAT_INDX_BASELINE_SUM|统计口径 + 统计维度 + 指标 + 数据归属 + 法人行号|保存金额类上期汇总基准|0055、0056、0058、0059、0062|

两表均遵守以下规则：

- `BASE_DATA_DATE`固定为活动/任务开始日前一天。
- `BASE_RUN_DATE`记录实际落库或补建日期。
- 同一业务主键已有基准时不覆盖。
- 金额指标先以明细表限定客户范围，再与汇总表关联并一次扣减汇总基准，避免逐客户金额基准存储。

---

## 7.3 指标聚合层

保存：

|字段|说明|
|-|-|
|data_date|统计日期|
|data_blng|统计主体|
|statis_dim|统计维度|
|statis_calib|统计路径|
|indx_code|指标编号|
|curnt_val|当前值|

|法人行号|数据隔离|

# 八、法人行号隔离设计

所有客户、账户、业务数据关联必须保持：

```
客户号
+
法人行号
```

联合条件。

原因：

避免不同法人主体下相同客户号造成数据污染。

# 十三、性能优化方案

## 13.1 避免重复扫描

优化：

公共基础数据提前计算。

---

## 13.2 避免客户级重复聚合

优化：

由：

```
客户
 ↓
机构汇总
```

调整为：

```
客户范围去重 + 客户级状态/归属计算
 ↓
按DATA_BLNG直接聚合
 ↓
机构递归上卷
```

说明：该优化仅消除“客户级金额结果表”的长期存储；不得跳过客户范围去重、客户等级跨越判断、临界客户判断或客户基准匹配。

---

## 13.3 SQL优化

检查：

- JOIN过滤条件
- 日期条件
- GROUP BY字段
- 大表关联顺序

避免：

```sql
WHERE TO_CHAR(date_col,...)
```

推荐：

日期范围过滤。

# 十五、最终设计结论

优化后的存储过程设计：

1. 保留双路径模型。
2. 路径A负责营销活动。
3. 路径B负责目标任务。
4. 两路径均支持机构和客户经理分类。
5. 客户只作为计算辅助，不作为输出维度；客户范围和状态基准仍持久化保存。
6. 金额类指标使用无客户的汇总基准，客户状态类指标使用带客户的明细基准。
7. 保留法人行号隔离。
8. 保留机构递归汇总能力。
9. 强化异常、事务、性能和验证设计。

该版本可作为开发、测试、DBA评审基础文档。
