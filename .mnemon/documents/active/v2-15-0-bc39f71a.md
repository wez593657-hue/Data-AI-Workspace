# 睡眠户唤醒存储过程 v2.16.1 改造设计

## 改造目标

睡眠户身份由上游 DWS 权威表 `DWS_CUST_DORMANT_ACCOUNT` 唯一决定；过程内不再以 AUM 或主动动账交易重新计算睡眠资格。实现采用**先身份、后属性**模式：先构建当日睡眠户清单，再仅针对清单客户补齐资产、机构、等级、名称和管户属性。

## 数据源与业务边界

`DWS_CUST_DORMANT_ACCOUNT` 是每日快照，字段为：

| 字段 | 类型 | 含义 |
|---|---|---|
| `PERSN_LEGAL_BK_CODE` | `VARCHAR(4)` | 客户所在法人行号 |
| `DATA_DATE` | `VARCHAR(8)` | YYYYMMDD 快照日期 |
| `CUST_ID` | `VARCHAR(20)` | 客户号 |

- **只处理个人客户**：DORMANT 数据须能内连接 `DWD_CUST_INDV_INFO`；不处理对公客户。
- **直接取当日快照**：`DATA_DATE = V_DATA_DATE`；当日没有记录时 DTL 过程报错 `-20003`，不回退 T-1。
- **机构不兜底**：`ORG_ID` 仅来自当日 `DWS_CUST_ASSE_LIAB`，缺失置空。
- **月内清单只增不减**：月初重置接触、唤醒状态；月内继承昨日明细并追加当日新产生睡眠户。
- **唤醒与接触口径保持不变**：唤醒为当月产品新增，接触为当月有效接触。

DDL：`data_assets/ddl/dws/dws_cust_dormant_account.sql`。

## v2.16.1 DTL 实现链路

1. **TMP1**：校验 DORMANT 表当日快照已就绪。
2. **TMP2**：预聚合定期、理财、保险账户业务日期落在当月窗口内的客户，写入 `TMP_ADS_SLEEP_WAKE_PROD`，作为唤醒状态来源。
3. **TMP3 下线**：不再预聚合近 365 天主动动账；临时表定义及清理保留，仅用于对账/回退。
4. **TMP4 下线**：不再全表预聚合 `DWS_CUST_ASSE_LIAB` 或构建 `TMP_ADS_SLEEP_DWS_WAKE`；临时表定义及清理保留，仅用于对账/回退。
5. **TMP5**：预聚合当月有效接触客户-管户经理组合。
6. **TMP6 [A] 清单基底**：
   - 月初：DORMANT 当日全量个人客户进入 BASE，余额置 0、名称/等级/管户/机构置空，接触与唤醒状态重置为 `0`；
   - 月内：继承昨日 DTL 的月度明细和累计状态。
7. **TMP7 [B] 增量追加**：当日 DORMANT 个人客户中，`(法人行号, 客户号)` 不在 BASE 的记录作为月内新产生睡眠户追加；同样仅写身份和状态占位。
8. **TMP8 [D1] 属性补全与唤醒**：
   - 按 BASE 客户键关联当日资产快照，补余额及 `ORG_ID`；无快照客户保留余额 0 和空机构；
   - 以相关子查询补名称、等级、理财管户经理，缺失时保留既有值；
   - 从 `TMP_ADS_SLEEP_WAKE_PROD` 全量判定 `WAKE_STATE`，已为 `1` 的状态不回退，且不依赖资产快照匹配。
9. **TMP8 [D2]**：沿用当月有效接触更新，`CNTCT_STATE='1'` 月内不可逆。
10. **写入 DTL**：在属性补全后写入 `ADS_CUST_SLEEP_WAKE_DTL`。

## 统计过程

`PRC_ADS_CUST_SLEEP_WAKE_STATIS` 已同步至 v2.16.1，但统计逻辑不变：仅聚合当日 DTL，按机构递归向上汇总和客户经理维度计算客户数、接触率与唤醒率。`ORG_ID` 为空的客户不进入机构维度，应监控其覆盖率。

## 性能与设计收益

- 清单身份和属性解耦，DORMANT 表成为唯一睡眠资格来源。
- 移除旧 AUM/主动动账睡眠判断及 `DWS_CUST_ASSE_LIAB` 全表预聚合分支。
- 资产快照只按 BASE 清单客户键关联，避免为非睡眠客户做属性处理。
- 唤醒状态独立于资产快照，避免无资产快照客户漏算唤醒。

## 待数据库验证

- DORMANT 当日快照与个人客户信息表的 JOIN 覆盖率；
- `ORG_ID IS NULL` 占比及机构统计影响；
- 月初全量重置、月内新增追加、唤醒/接触不可逆、无资产快照客户唤醒上翻、当日快照缺失报错、当日重跑幂等性；
- 新旧睡眠户口径客户数差异；
- Kingbase 环境中 `UPDATE ... FROM` 及相关子查询 `ROWNUM = 1` 的编译与执行验证。
